# agent-prompt-assembly Specification

## Purpose
确定性地把一个工作流 `agent` 节点拼成它提交给 AI 的完整 prompt（回复语言 + 宪法 + 任务 + 需求卡占位 + 可写范围 + 产出/模板），需求卡以按字段分子标题的注入槽表示、产出模板用代码块围栏包裹、执行配置与客观门不入文本。此拼装为「查看完整 prompt」预览与将来 agent 执行器的单一来源。

## Requirements

### Requirement: 拼装 agent 节点的完整 prompt

系统 SHALL 提供一个**确定性纯函数**,把一个 `agent` 执行者节点拼成它提交给 AI 的**完整 prompt 文本**。拼装 MUST 是确定的:相同输入恒产出逐字相同的结果,不依赖时间/随机/外部状态。读 skill 文件、解析宪法治理、解析模板引用等副作用 MUST 留在调用方,拼装函数只接收**已解析**的内容。

完整 prompt MUST 按固定顺序包含以下层(空层按本规格省略或给默认说明,不留空标题):

1. **回复语言**:据设置里的界面语言(`zh`/`en`)要求 AI 用对应语言回复与产出。该层 MUST 恒在;指令本身 SHOULD 以目标语言书写以免歧义。
2. **宪法**:该项目的生效宪法各条(名称 + 正文),保持派生的稳定顺序(见 `project-constitution`)。生效宪法为空时,该层整节省略。
3. **任务**:节点的 prompt——`inline` 形态用其文本;`file` 形态用**已读出的** skill 文件内容。
4. **需求卡**:MUST 按**字段分子标题**布局——每个卡字段一个 `##` 子标题(至少:标题、类型、描述、关系),其下一行是该字段的**运行期注入槽**(编辑期为占位文案、形如 `{运行时注入：…}`,执行期替换为卡的真实字段值)。此层 MUST 恒在(不随是否有卡而消失,因编辑期是模板、无具体卡)。这把"卡注入成什么结构"钉死,使预览与执行同构。
5. **涉及的成员仓**(执行期注入多仓布局):MUST 由**引擎注入**本需求涉及的各成员仓(仓名/标签/worktree 路径/哪个是当前工作目录、哪些是额外目录),让 agent 明确多仓布局,而非把仓名/路径写死在节点 prompt。空(单仓/预览)时该层省略。
6. **可写范围**:节点 `writableScope` 各条;为空时 MUST 给出「整条分支可写」之类的默认说明,而非省略。
7. **产出**:MUST 以**引导语**开头,说明这些是 agent 完成后需产出的文件。每个产出 MUST 标清其目的地路径(路径为空给「未指定路径」提示)与必选/可选,并附其模板——模板为规则库 `ref` 时 MUST 拼入**已解析**的 `output-template` 内容,且模板原文 MUST 用**代码块围栏**包裹并附前导语(说明这是模板原文、其中 `<!-- -->` 写作指引不要保留到产出),以与外层分节区隔、避免模板内的 `##` 标题被误读为 prompt 分节;模板为 `none` 时注明无固定模板。产出为空时该层整节省略。
8. **引擎交互协议**:MUST 恒在(与是否有具体需求卡无关)。此层告诉 agent 如何与引擎结构化交互——MUST 说明:完成/需要决策/失败时把**握手文件**写到**引擎注入的绝对路径**(在 worktree 之外、不污染代码仓;预览态用占位)并退出,握手结构含 `status`(`done`/`need-decision`/`failed`)、`decision`(need-decision 时给选项与是否允许自由输入)、`repos`(涉及成员仓判定,供下游收窄)、`note`(小结);并说明 stdout 仅供展示、结构化意图必须走握手文件。此层与 `agent-execution` 的握手合约同源、互为约束。

执行配置(工具 / 模型 / 额外参数)MUST NOT 进入 prompt 文本——它是 CLI 调用形态,不是消息内容。**客观门**(自动校验由 gate 自动执行、人工评审是给人的动作按钮)MUST NOT 进入 prompt 文本——它们不是给 agent 的指令。

#### Scenario: 全层齐备按固定顺序拼装
- **WHEN** 一个 agent 节点带非空 prompt、项目有生效宪法、声明了可写范围与产出(含模板),且调用方已解析好各层内容
- **THEN** 函数产出按「回复语言 → 宪法 → 任务 → 需求卡占位 → 涉及成员仓 → 可写范围 → 产出 → 引擎交互协议」顺序排列的完整 prompt 文本

#### Scenario: 回复语言据设置注入
- **WHEN** 设置语言为 `zh`(或 `en`)
- **THEN** prompt 含一条要求 AI 用简体中文(或英文)回复的指令,且该层位于最前

#### Scenario: 需求卡按字段分子标题、每字段带注入槽
- **WHEN** 拼装任意 agent 节点(编辑期无具体需求卡)
- **THEN** 结果在需求卡层为每个字段(至少 标题/类型/描述/关系)输出一个 `##` 子标题 + 一行运行期注入槽占位,保持字段固定顺序

#### Scenario: 产出带引导语、模板原文用代码块围栏包裹
- **WHEN** 节点声明了一个或多个产出
- **THEN** 产出层以引导语开头,每个产出标清路径与必选/可选;模板为 `ref` 时拼入已解析内容并以代码块围栏包裹、附前导语,为 `none` 时注明无固定模板、ref 解析不到时给降级提示

#### Scenario: 空层省略或给默认说明
- **WHEN** 生效宪法为空或产出为空
- **THEN** 对应层整节省略、不留空标题;而可写范围为空时给出「整条分支可写」的默认说明

#### Scenario: 多仓布局由引擎注入而非写死节点 prompt
- **WHEN** 执行期注入本需求涉及的成员仓(如 web 前端-当前目录、api 后端-额外目录)
- **THEN** prompt 含「涉及的成员仓」层列出各仓名/标签/路径与主-额外目录;单仓/预览态则省略该层

#### Scenario: 引擎交互协议层恒在并说明握手契约
- **WHEN** 拼装任意 agent 节点(无论是否有具体需求卡、是否声明产出),注入了握手绝对路径
- **THEN** prompt 含「引擎交互协议」层,说明把握手写到该绝对路径(worktree 之外,含 status/decision/repos/note)与「stdout 仅展示、结构化意图走握手文件」

#### Scenario: 执行配置与客观门不进 prompt 文本
- **WHEN** 节点声明了执行配置(工具/模型/额外参数)与客观门
- **THEN** 拼装出的 prompt 文本不含执行配置字段,也不含客观门内容

#### Scenario: 拼装确定可复现
- **WHEN** 以相同输入多次调用拼装函数
- **THEN** 每次产出逐字相同

### Requirement: 拼装器为预览与执行器的单一来源

「查看完整 prompt」预览与将来 agent 执行器实际提交给 AI 的 prompt MUST 由**同一个**拼装函数产出,二者不得各自实现一套拼装逻辑。预览与执行的差异 MUST 仅来自输入(预览的需求卡为占位、执行期注入真实卡),而非拼装规则不同。

#### Scenario: 预览与执行同源
- **WHEN** 预览渲染某 agent 节点的完整 prompt,而将来执行器提交同一节点
- **THEN** 二者经同一拼装函数产出;除需求卡(预览占位 / 执行真实卡)外,层次、顺序与格式一致



### Requirement: 只读回退判定任务段

拼装器 SHALL 提供一个纯函数 `rollbackJudgmentTask(input)`,产出只读回退判定 agent 的 `# 任务` 段正文——告知它是本需求的只读顾问、不改任何文件不写产出;给出用户驳回意见与产物溯源关系;要求判断意见指向的问题最早在哪个节点产生、该回到哪个节点修复(给一个主选节点 + 若干备选),把结论写进握手决策交用户确认;强调回退是回到该节点在现有进展上修复、不重置不作废下游。正文与 `docs/failure-handling.md` §6.6 单一来源。

配合该任务段,只读判定 agent 的完整 prompt MUST 以 `writableScope=[]`、`outputs=[]` 调 `assembleAgentPrompt`,使结果**不含**「可写范围」与「产出」两段(强调只读)。

#### Scenario: 生成只读回退判定任务段
- **WHEN** 以驳回意见与溯源上下文调用 `rollbackJudgmentTask`
- **THEN** 返回的任务段声明只读、要求给出主选+备选回退节点并写进握手,不含任何改代码指令

#### Scenario: 只读 prompt 省略可写范围与产出段
- **WHEN** 以 `writableScope=[]`、`outputs=[]` 及回退判定任务段调 `assembleAgentPrompt`
- **THEN** 拼出的 prompt 不含「可写范围」与「产出」两节

### Requirement: 修复前向续接注入段

拼装器 SHALL 支持在续接注入中生成「修复前向」增量段——告知目标节点执行者:本需求之前已推进到最远节点 N、用户在评审门驳回的意见、请在现有进展(worktree 已有下游改动)上修复,别推倒重来。它与既有的「用户对提问的决定」「失败详情」增量段并列,按情形拼接。

#### Scenario: 拼接修复前向注入
- **WHEN** 引擎重入目标节点并要求续接注入,带最远进展节点与驳回意见
- **THEN** 增量段告知已推进到最远节点、驳回意见,并要求在现有 worktree 进展上前向修复
