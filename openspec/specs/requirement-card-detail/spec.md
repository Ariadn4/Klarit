# requirement-card-detail Specification

## Purpose
需求卡详情面板：点开一张看板卡后集中展示卡信息（标题、描述、类型、生命周期状态、预取名标识）、运行控制（未运行时「运行」，运行中「暂停」/「恢复」，命令执行者节点手动推进——非末节点转后台/中止推进、末节点中止并完成流程）、单卡决策呈现（迁自 dogfood 的 i18n 决策 UI，复用统一决策结构、跨卡决策弹窗不在本能力范围）、命令输出按前台/各后台任务分流可回看（后台命令终止后保留并标注终态、可清除，输出依赖引擎分桶缓冲、关重开后仍可回看）、卡上分支名仅在分支真正落地后展示引擎实际分支名并可点跳转联动 git 视图，并退役临时的 dogfood 试跑卡。对齐 `docs/project-goals.md`「单卡决策直接展示在需求卡详情面板内，跨卡决策单独弹窗」，UI 遵守 `docs/brand` 与设计令牌（仅语义令牌、深浅双主题）。
## Requirements
### Requirement: 需求卡详情面板

系统 SHALL 在点击看板上一张需求卡时打开一个**需求卡详情面板**,展示该卡的标题、描述(markdown 渲染)、类型徽章、生命周期状态、预取名(作卡标识,非分支——分支仅在真正建出后另行展示,见下),以及——当卡有关联运行(`activeRunId`)时——其运行控制、决策呈现与命令输出入口。面板 MUST 遵循 `docs/brand` 与设计令牌(仅语义令牌、深浅双主题)。

#### Scenario: 点卡打开详情
- **WHEN** 用户点击看板上一张需求卡
- **THEN** 打开该卡详情面板,展示其标题、描述、类型、状态与预取名标识

#### Scenario: 无运行卡的详情
- **WHEN** 打开一张尚未运行(无 `activeRunId`)的卡详情
- **THEN** 展示卡基本信息与「运行」入口,不展示运行控制/决策/输出区

### Requirement: 详情面板的运行控制

需求卡详情面板 SHALL 提供该卡的**运行控制**:未运行时提供「运行」(从卡派生运行请求并触发引擎,见 `requirement-card-store`);运行中提供「暂停」/「恢复」。运行控制 MUST 经既有引擎 IPC(`start`/`pause`/`resume`)操作,渲染层不持有运行生命周期。

当当前节点为 **`command` 执行者且正在执行**(长驻命令如 `npm start` 不会自行退出)时,详情面板 SHALL 额外提供**手动推进控件**(经既有 `advanceCommand`):非末节点给「进入下一节点(转后台)」与「中止并进入下一节点」;**末节点给「中止并完成流程」**——使运行中止该命令并走到终局(已完成),否则运行会永远卡在该命令节点、任务无法完成。手动推进 MUST NOT 被当作命令失败、不抛失败决策。

#### Scenario: 从详情触发运行
- **WHEN** 用户在一张可运行卡的详情面板点「运行」
- **THEN** 系统从该卡派生运行请求并经引擎 `start` 触发,卡获得 `activeRunId`、进入进行中

#### Scenario: 暂停与恢复
- **WHEN** 用户对一张进行中卡的运行点「暂停」再点「恢复」
- **THEN** 经引擎 `pause`/`resume`,运行在阶段边界暂停后又从断点续跑

#### Scenario: 末节点长驻命令可中止并完成流程
- **WHEN** 一张卡的运行停在**末节点**的 `command` 执行(长驻命令不退出)
- **THEN** 详情面板提供「中止并完成流程」按钮,点击后引擎中止该命令并使运行走到终局(卡进入已完成),不抛失败决策

#### Scenario: 非末节点命令可转后台或中止推进
- **WHEN** 一张卡的运行停在**非末节点**的 `command` 执行
- **THEN** 详情面板提供「进入下一节点(转后台)」与「中止并进入下一节点」,点击后运行推进到下一节点(转后台者保留后台命令)

### Requirement: 单卡决策在详情面板内呈现

当一张卡的关联运行处于 `waiting-decision` 时,系统 SHALL 在**该卡详情面板内**呈现其决策(对齐 `docs/project-goals.md`「单卡决策直接展示在需求卡详情面板内,跨卡决策单独弹窗」)。决策交互 SHALL 采用**统一「选中 + 提交」**模型(对齐 `docs/failure-handling.md` §2.1「选一个选项、和/或写内容,再点提交才生效」):

- `options` 渲染为**可选中项**(单选 `◉/○`、`multi` 时多选 `☑/☐`),点击只切换选中、**不即时生效、不推进运行**;
- 可选 `input` 为自由输入框;
- 面板底部有**唯一「提交」按钮**——选一项、和/或写内容后提交,才经引擎 `decide(runId, { optionId? | optionIds? | text? })` 生效;选项与输入**皆空时提交禁用**;
- `titleKey`(+ `titleParams`)翻译后作背景说明;每个选项的 `detailKey`/`detail` **常显在该选项下方**(不藏悬浮提示);`recommended` **仅在有多个选项时**以「推荐」标呈现(独一份选项不标);`reason` 为用户可读失败原因(不加「原因：」标签前缀);`gateHistory` 为重试历史;`raw`(原始底层输出)MUST NOT 在正式 UI 渲染(仅 dev/test)。

文案随当前语言实时翻译。跨卡决策弹窗不在本能力范围。

**提交是异步的,期间显式「处理中」态**:决策提交后到引擎驱动到下一停点之前(走 IPC + 可能拉起 agent),面板 MUST 进入「处理中」态——**保留已选中项与输入不清空**、锁住选项/输入/提交(提交按钮显示「处理中…」),**不留空白可点的死等状态**;新决策到达(决策 `source` 变化)即复位重画,同一决策再弹则由提交流程兜底复位。

**动作按钮为切换态、不推进运行**:`actions` 里的每个动作按钮触发的是一个**旁路进程**(如启动后端/前端 dev server、跑验收命令),**不**提交决策、**不**推进运行(与前进式 `options` 正交——只有提交才续跑)。每个动作按钮 SHALL 据其**对应进程的运行态**在两态间切换:该动作**无活进程**时呈现为「启动」(点击触发,经引擎起一条独立后台进程,见 `engine-execution`);该动作**有活进程**时呈现为「中止」(点击停掉该进程)。动作运行态 MUST 由该运行**当前后台命令列表**按动作身份**派生**(不把易变的活进程态塞进持久决策),使切换态与真实进程一致。

#### Scenario: 等待决策时在详情内显示决策
- **WHEN** 一张卡的运行进入 `waiting-decision`
- **THEN** 该卡详情面板内显示其决策(背景说明 + 可选中选项 + 可选输入 + 提交按钮),不弹独立窗口

#### Scenario: 选项需选中再提交、不即点即生效
- **WHEN** 用户点某个选项
- **THEN** 该选项被选中(高亮 + 单选 `◉` / 多选 `☑`),运行不因此推进;须再点「提交」才经 `decide` 生效

#### Scenario: 唯一提交按钮承载选项与输入
- **WHEN** 用户选了选项、和/或在 `input` 写了内容后点「提交」
- **THEN** 经 `decide` 提交对应 `optionId`/`optionIds`/`text`;选项与输入皆空时提交按钮禁用

#### Scenario: 选项详情常显、推荐仅多选项时标注
- **WHEN** 某选项带 detail,且决策含多个选项、其一为 `recommended`
- **THEN** 该选项的 detail 文本常显在其下方(非悬浮);「推荐」标注只在有多个选项时出现,独一份选项不标

#### Scenario: 提交后进入「处理中」态而非空白死等
- **WHEN** 用户提交决策,引擎尚未驱动到下一停点
- **THEN** 面板保留选中与输入、锁住交互、提交按钮显示「处理中…」;待新决策到达或异步兑现后复位,不出现选中被清空、按钮变灰的空白死态

#### Scenario: 经卡上红点跳转定位到决策
- **WHEN** 用户点击看板卡上的静止红点(等待决策)入口
- **THEN** 打开该卡详情面板并定位/滚动到决策区,使其可见可操作

#### Scenario: 动作按钮不推进运行、据进程运行态在启动/中止间切换
- **WHEN** 用户点某动作按钮的「启动」起了对应旁路进程,该进程仍在跑
- **THEN** 该动作按钮就地变为「中止」、决策仍在(不提交、不推进);点「中止」停掉该进程后又变回「启动」;各动作按钮各自独立切换、互不影响

#### Scenario: 原始输出不在正式 UI 渲染
- **WHEN** 一个决策携带 `raw` 字段
- **THEN** 正式 UI 不渲染 `raw`(仅 dev/test 可见),用户只看 `titleKey`/`reason` 等可读文案

#### Scenario: 决策文案随语言实时翻译
- **WHEN** 用户在决策展示期间切换界面语言
- **THEN** 决策的背景与选项文案据新语言实时翻译

### Requirement: 命令输出按前台/各后台任务分流且可回看

需求卡详情面板 SHALL 为该卡运行的命令输出提供**按条分流、可回看**的入口,而非把多条命令输出杂糅一处:

- **前台当前命令**:以运行圆点(呼吸蓝点)及其后方节点文案作为入口,点击后展示**当前运行命令**的输出。
- **各后台命令**:展示该运行的后台命令条目(每个 `bgId` 一行,带其节点/标签),每行可点入查看**该后台命令各自**的输出(可同时存在多个后台命令)。**人工门动作按钮触发的进程亦为后台命令**,同样各占一格独立展示其输出(以该动作文案为标签),MUST NOT 混入「前台当前命令」——两个动作(如启动后端、启动前端)的输出 SHALL 各自一格、绝不夹揉在同一处。

**后台命令终止后 MUST NOT 直接消失**:一个后台命令被用户中止 / 自行退出 / **超时被杀**时,其条目 SHALL **保留在详情面板并标注终态**(如「已中止」「已结束」「已超时中止」——尤其"计时中止"要显式可见,以免用户误以为是 bug),直到**用户点击「清除」**才移除该条目;运行中的后台命令则提供「中止」。终态条目的输出仍 SHALL 可回看。**但运行推进进入新节点时**,系统 SHALL **自动清掉**上个节点残留的**已终止**后台命令条目(避免跨节点攒一堆死窗口);**仍在运行**的转后台命令条目 MUST 保留。

输出 MUST **可回看**(不只在流过时即时显示):依赖引擎对命令输出按命令/后台任务分桶缓冲(见 `engine-execution`);**命令转后台后其后续输出归入该后台命令自己的桶**(不再混入前台节点桶)。关闭重开后,仍能回看运行期内已缓冲的输出。

**输出文本可选中、可一键复制**:每个输出展示(前台命令、AI 活动输出、各后台命令,以及「查看 prompt」里 AI 的输入文本)SHALL **允许用户选中其中任意文字**(局部覆盖界面全局的禁选默认),供自行 Ctrl+C 复制片段。每个输出框 SHALL 另提供一个**一键复制全部**入口:一个 **hover 才浮现**于输出框角落的复制按钮,点击把**该输出桶的完整缓冲文本**(底层字符串、换行完整,与视觉换行无关)写入系统剪贴板,并给短暂的「已复制」反馈后复原;**输出为空时不渲染该按钮**。复制经引擎/主进程的剪贴板通道(Electron `clipboard`)完成,不依赖浏览器剪贴板 API。

#### Scenario: 经蓝点入口看前台命令输出
- **WHEN** 一张卡运行中其前台节点正在跑命令(呼吸蓝点),用户点击该点/文案入口
- **THEN** 展示当前命令的输出(可回看已产出的部分,非仅实时片段)

#### Scenario: 多个后台命令各自可点入查看
- **WHEN** 某运行有两个以上后台命令
- **THEN** 详情面板分别列出每个后台命令,各有独立入口查看其各自输出(转后台后的输出进各自的桶,不再是「暂无输出」)

#### Scenario: 两个动作进程输出各自一格不夹揉
- **WHEN** 用户在验收门先后点「启动后端」「启动前端」,两个动作进程同时在跑
- **THEN** 详情面板为两个进程各展示一格独立输出(以各自动作文案为标签),两条输出互不混入、也不进「前台当前命令」;可分别中止其一而不影响另一

#### Scenario: 后台命令超时中止后保留并标状态
- **WHEN** 一个带超时的后台命令到点被杀
- **THEN** 其条目保留在详情面板并标注「已超时中止」(不直接消失),并提供「清除」按钮;用户点「清除」后方移除该条目

#### Scenario: 输出文本可被用户选中
- **WHEN** 用户在任一输出展示(命令/AI/后台/prompt)里按下并拖选一段文字
- **THEN** 该段文字可被正常选中(不受界面全局禁选影响),用户可用系统快捷键复制所选

#### Scenario: 一键复制全部输出并给反馈
- **WHEN** 某输出框有内容,用户点击其角落的复制按钮
- **THEN** 该输出桶的完整缓冲文本被写入系统剪贴板,按钮短暂显示「已复制」后复原

#### Scenario: 空输出不渲染复制按钮
- **WHEN** 某输出框当前没有任何缓冲文本
- **THEN** 不渲染其复制按钮(无内容可复制)

### Requirement: 退役 dogfood 试跑卡

本能力落地后,临时的 dogfood 试跑卡(`DogfoodRunCard` / `DogfoodPanel` / `dogfood-cards`)SHALL 被移除——其运行控制与 i18n 决策 UI 已迁入需求卡详情面板的可复用决策组件。移除后系统 MUST 不再依赖 dogfood 路径触发或观察运行。

#### Scenario: dogfood 卡不再存在
- **WHEN** 本能力实现完成
- **THEN** 代码库不再含 dogfood 试跑卡及其面板,运行的触发/决策/输出均经需求卡详情面板

### Requirement: 卡上按成员仓展示已建分支并联动 git 视图

需求卡的**预取名**只是"打算用的分支名",不代表已有分支;卡面 MUST NOT 在分支尚未创建时展示。仅当该卡的运行在某成员仓**真正建出该分支**(探测确认该成员仓本地分支存在)时,才 SHALL 为**每个已建出分支的成员仓各展示一个可点条目(chip)**;多个成员仓的条目 SHALL **内联平铺**(不折叠)。

条目 SHALL 以「**成员仓名/分支名**」标识(如 `web/test-create-card`)。分支名 MUST 是**引擎实际使用的分支名**(统一递增避撞后可能与预取名不同,见 `engine-execution`),而非预取名。**展示门控是「分支已建出」而非「worktree 已建出」**——分支一建出即展示,不等 worktree。

每个条目 SHALL **可点击**:点击后侧边栏切到 git 视图并**程序化聚焦**到 (该条目对应的成员仓, 该分支)(见 `sidebar-git-view`)——聚焦到点中的那个成员仓,而非一律首仓:

- 该分支**已建出 worktree** → git 视图展示其 worktree 目录文件树。
- 该分支**尚未建出 worktree** → git 视图展示「暂未创建 worktree」空态(复用 `sidebar-git-view` 既有空态),而非跳转失败或空白。

某成员仓的**分支被删除**(如交付后 `delete-branch`)后,其条目 SHALL 从卡面消失(卡面仅展示当前实际存在分支的成员仓);worktree 被单独回收但分支仍在时,条目**仍在**、点击落到「暂未创建 worktree」空态。面板 MUST 遵循 `docs/brand` 与设计令牌(仅语义令牌、深浅双主题)。

#### Scenario: 分支未建出时不展示
- **WHEN** 一张卡尚未运行、或运行尚未在任何成员仓建出分支
- **THEN** 卡面不展示任何分支条目(预取名不作分支展示)

#### Scenario: 分支建出即按成员仓内联平铺展示条目
- **WHEN** 一张卡的运行已在成员仓 A、B 各建出分支(worktree 尚未建)
- **THEN** 卡面为 A、B **各展示一个可点条目**、内联平铺,条目以「成员仓名/分支名」标识,分支名为引擎实际使用的分支(非预取名)

#### Scenario: 点条目且 worktree 已建 → 定位其 worktree
- **WHEN** 用户点击成员仓 B 的条目,且 B 的该分支已建出 worktree
- **THEN** 侧边栏切到 git 视图并聚焦到 (成员仓 B, 该分支),下方展示其 worktree 目录文件树

#### Scenario: 点条目但 worktree 未建 → git 视图给「暂未创建 worktree」空态
- **WHEN** 用户点击成员仓 B 的条目,而 B 的该分支尚未建出 worktree
- **THEN** 侧边栏切到 git 视图并聚焦到 (成员仓 B, 该分支),git 视图展示「暂未创建 worktree」空态(不崩溃、不空白)

#### Scenario: 成员仓分支被删除后其条目消失
- **WHEN** 某成员仓的该分支被 `delete-branch` 删除
- **THEN** 该成员仓的条目从卡面消失,其余仍有该分支的成员仓条目照常展示

#### Scenario: 单仓卡退化只展示一个条目
- **WHEN** 一张单仓卡的运行建出其唯一成员仓的分支
- **THEN** 卡面展示一个条目(该唯一成员仓名/分支),点击聚焦到该唯一成员仓的 (分支, worktree 或空态)
