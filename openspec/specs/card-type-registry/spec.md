# card-type-registry Specification

## Purpose
需求卡「类型」的可自定义机制：引擎内置两种封闭的流动原型（`container`/`leaf`），用户在其上定义命名类型（名称/描述/原型/徽章颜色）。类型为**项目级**（每个项目一份，存 `project.cardTypes`），未设置时回落默认种子（epic/feature/bug）。工作流可声明建议类型、激活时幂等播种进项目；设置页提供类型的增删改与自动生成分解 skill 的预览。

## Requirements

### Requirement: 流动原型为引擎内置封闭词表

系统 SHALL 内置一个封闭的**流动原型（archetype）**词表，恰含两个值：`container`（容器）与 `leaf`（子叶）。原型是引擎解析卡片流动与关系合法性的唯一机制来源，MUST 写死在引擎、不对用户开放扩展。两个原型的语义 MUST 为：

- `container`：**不逐列流动**。容器卡停在「待办」列作为子卡入口；其旗下子卡全部归档后，容器卡从「待办」直达「归档」。容器卡 MAY 挂子卡（含嵌套其它容器卡）。
- `leaf`：**逐列流动**，是看板的流通单位，按**项目激活工作流**的阶段（看板列）逐列推进。同一项目所有 leaf 卡共用这一条工作流的列（类型本身不带工作流）。叶子卡 MUST NOT 挂子卡。

#### Scenario: 原型只取两值之一
- **WHEN** 校验某类型声明的 archetype
- **THEN** 取 `container` 或 `leaf` 方为合法；其它值判为非法

#### Scenario: 容器不逐列流动
- **WHEN** 引擎按某容器原型类型的卡解析流动
- **THEN** 该卡停在「待办」列、不逐列推进；其子卡全部归档后该卡直达「归档」

#### Scenario: 子叶按项目工作流逐列流动
- **WHEN** 引擎按某子叶原型类型的卡解析流动
- **THEN** 该卡按项目激活工作流的阶段逐列推进（与同项目其它 leaf 卡共用同一套列）

### Requirement: 需求卡类型定义（CardTypeDef）

系统 SHALL 以一份结构化定义表达一个**需求卡类型**。一个类型定义 MUST 含：

- **id**：稳定标识（卡片以此引用类型），非空。
- **name**：显示名（看板/审阅徽章用），非空。
- **description**：该类型的语义说明，**作为分解 skill 的 AI 分类依据**（写给 LLM 看的分类指令，而非 UI 提示文案）。
- **archetype**：`container` 或 `leaf` 之一，决定该类型的流动与关系行为。
- **color**（可选）：徽章颜色，取自封闭预置颜色盘（装饰性标签色，与品牌/语义色分离）；缺省回落默认色。

类型定义**不含工作流引用**——项目流动由项目激活的单一工作流统一承载，类型只表达语义与原型。

#### Scenario: 完整类型定义可表达并往返保持
- **WHEN** 构造一个含 id、name、description、archetype 的类型定义并序列化后读回
- **THEN** 各字段完整保留

#### Scenario: 类型定义不携带工作流
- **WHEN** 读取任一类型定义
- **THEN** 其结构不含工作流引用字段（流动由项目激活工作流统一决定）

#### Scenario: 徽章颜色取自预置盘
- **WHEN** 校验一个声明了 color 的类型定义
- **THEN** color 在预置颜色盘内方为合法；非法颜色判为非法；缺省 color 合法（回落默认色）

### Requirement: 类型集的持久化与增删改查

系统 SHALL 为**每个项目**维护一份**需求卡类型集**，持久化于该项目的注册表记录（`project.cardTypes` @ userData，不入 git；与 `activeWorkflowId`/`constitution` 并列、按项目身份关联），并经 IPC 暴露给渲染层对**当前绑定项目**的查看、新增、编辑、删除。未设置时回落默认类型（见下「默认类型种子」）。删除一个仍被在册卡片引用的类型时，系统 MUST 不静默丢弃引用——SHALL 阻止删除或要求改派，返回可读原因。同一项目内类型 id MUST 唯一。

#### Scenario: 增删改查类型
- **WHEN** 用户经设置页对当前项目新增/编辑/删除一个自定义类型
- **THEN** 变更持久化到该项目的注册表记录，再次读取可见最新结果

#### Scenario: 类型集按项目隔离
- **WHEN** 在项目 A 增改其类型集
- **THEN** 不影响项目 B 的类型集（各项目独立）

#### Scenario: 类型 id 唯一
- **WHEN** 新增的类型 id 与在册类型重复
- **THEN** 操作被拒、返回可读原因

#### Scenario: 阻止删除被引用的类型
- **WHEN** 用户删除一个仍被某需求卡引用的类型
- **THEN** 系统拒绝删除（或要求先改派引用卡片），返回可读原因，不留下悬挂引用

### Requirement: 默认类型种子

系统 SHALL 在项目类型集**未设置**时回落一组**默认类型**，至少含 `epic`（archetype `container`）、`feature`（archetype `leaf`）、`bug`（archetype `leaf`），使开箱即用，并作为老数据 `category→typeId` 映射的落点。默认类型 MUST 可被用户编辑或停用（与自定义类型同等对待），不写死、不强制保留。

#### Scenario: 未设置类型集时回落默认
- **WHEN** 读取一个尚未设置过类型集的项目
- **THEN** 得到 `epic`(container)、`feature`(leaf)、`bug`(leaf) 三个默认类型

#### Scenario: 默认类型可编辑
- **WHEN** 用户编辑或删除一个默认类型
- **THEN** 系统按普通类型处理该操作（不强制保留默认类型）

### Requirement: 工作流激活播种建议类型

工作流定义 MAY 声明一组**建议类型**（`container` / `leaf` 皆可，见 `workflow-definition` 的 `suggestedTypes`）。当项目激活一条工作流时，系统 SHALL 把该工作流声明的建议类型**播种**进**该项目**的类型集：尚不存在（按 id）的类型被加入；已存在的 id **跳过、不覆盖**用户已有的同名类型（幂等）。播种后类型归该项目所有、与别的项目隔离，**停用或更换工作流 MUST NOT 删除或孤儿化**已在册的类型与引用它的卡片。

#### Scenario: 激活工作流播种其建议类型
- **WHEN** 项目激活一条声明了建议类型的工作流，且该项目类型集尚无这些 id
- **THEN** 这些类型被加入该项目类型集，可供卡片引用与分解使用

#### Scenario: 播种幂等不覆盖已有类型
- **WHEN** 激活的工作流建议类型 id 与注册表已有类型重复
- **THEN** 跳过该 id、保留用户已有定义，不覆盖

#### Scenario: 停用工作流不孤儿化类型
- **WHEN** 项目停用或更换工作流，而某些卡片仍引用此前播种的类型
- **THEN** 这些类型仍留在注册表、卡片引用不悬挂

### Requirement: 设置页的需求卡类型管理

系统 SHALL 在设置页提供一个**需求卡类型**管理区（归项目设置、管理当前绑定项目；未绑定项目显示空态），让用户查看在册类型列表，并新增/编辑/删除类型——可设置 `name`、`description`、`archetype`、`color`。该界面 MUST 遵循品牌规范（语义令牌、深浅两套）、对齐现有规则库/工作流库设置区的结构与交互，并对非法输入（空名、删除被引用类型等）给出可读提示。

#### Scenario: 在设置页查看类型列表
- **WHEN** 用户打开设置页的需求卡类型区
- **THEN** 显示在册类型列表，每项含名称、描述、原型（container/leaf）徽章

#### Scenario: 在设置页新增自定义类型
- **WHEN** 用户填写名称、描述、选择原型与颜色并保存
- **THEN** 新类型加入注册表并即时出现在列表中

#### Scenario: 删除被引用类型给出提示
- **WHEN** 用户尝试删除一个仍被卡片引用的类型
- **THEN** 界面给出可读提示、阻止删除或要求先改派，不留悬挂引用

### Requirement: 类型管理处预览自动生成的分解 skill

设置页的需求卡类型管理区 SHALL 提供对**自动生成的分解 skill** 的只读预览：展示由"固定拆分模板 + 当前在册类型的 name/description"合成的完整生效分解 skill 文本（见 `requirement-decomposition`），使用户改类型描述后能直观看到分解 prompt 随之变化。预览 MUST 反映注册表当前状态（含用户刚编辑的类型描述）。

#### Scenario: 预览随类型描述更新
- **WHEN** 用户在类型管理区查看自动生成的分解 skill 预览，并修改某类型的描述
- **THEN** 预览文本相应反映该类型的新描述

#### Scenario: 预览为完整生效 skill
- **WHEN** 用户打开分解 skill 预览
- **THEN** 显示包含拆分模板与全部在册类型分类段的完整生效 skill 文本（只读）
