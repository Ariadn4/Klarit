# manage-projects-window Specification

## Purpose
定义独立的「管理项目」窗口：从侧边栏切换器子菜单打开，集中列出注册表中所有已导入项目、支持点击打开、显示文件夹、从列表移除，并提供品牌信息与「打开本地项目」入口。
## Requirements
### Requirement: 管理项目窗口

系统 SHALL 提供一个独立的「管理项目」窗口，由切换器子菜单的「管理项目…」入口打开。该窗口左侧为项目清单区、右侧为品牌与入口区。窗口在任意时刻 MUST 只存在一个实例：重复触发打开 MUST 聚焦已有的管理项目窗口而非新建。

#### Scenario: 从切换器打开管理项目窗口
- **WHEN** 用户点击切换器子菜单中的「管理项目…」
- **THEN** 系统打开管理项目窗口，左侧显示项目清单、右侧显示品牌与「打开本地项目」入口

#### Scenario: 已打开时不重复新建
- **WHEN** 管理项目窗口已打开，用户再次点击「管理项目…」
- **THEN** 系统将已存在的管理项目窗口聚焦置前，不新建第二个

### Requirement: 左侧项目清单

管理项目窗口左侧 SHALL 列出注册表中所有已导入项目，每个条目 MUST 显示项目名与其当前记录路径。清单 MUST 反映注册表的当前内容；当某项目被移除后，清单 MUST 不再显示该项目。

#### Scenario: 列出全部已导入项目
- **WHEN** 用户打开管理项目窗口且注册表中有若干已导入项目
- **THEN** 左侧逐条列出每个项目的名称与路径

#### Scenario: 无已导入项目时
- **WHEN** 注册表中没有任何已导入项目
- **THEN** 左侧清单为空（不列出任何项目条目），右侧入口仍可用

### Requirement: 点击项目条目打开项目

在管理项目窗口左侧清单中直接点击某个项目条目（非三点按钮区域）时，系统 SHALL 以与主窗口侧边栏切换器子菜单中打开项目完全一致的窗口路由打开该项目（见 `workspace-windows`）：该项目已有打开的窗口则聚焦置前；当前无绑定的空状态窗口则在该窗口打开；否则新开窗口。打开动作完成后系统 MUST 关闭管理项目窗口。

#### Scenario: 该项目已有窗口则聚焦
- **WHEN** 用户点击的项目已有一个打开着的窗口
- **THEN** 系统将那个窗口聚焦置前，并关闭管理项目窗口，不新建窗口

#### Scenario: 存在空状态窗口则就地打开
- **WHEN** 用户点击的项目尚无打开窗口，且存在一个未绑定任何项目的空状态窗口
- **THEN** 系统在该空状态窗口打开所选项目，并关闭管理项目窗口

#### Scenario: 否则新开窗口
- **WHEN** 用户点击的项目尚无打开窗口，且没有可用的空状态窗口
- **THEN** 系统新开一个窗口打开所选项目，并关闭管理项目窗口

### Requirement: 项目条目的三点子菜单

每个项目条目 SHALL 提供一个「三个点」按钮，点击弹出子菜单，菜单 MUST 含两项：「在资源管理器中显示文件夹」与「从项目列表中移除」。点击三点按钮或其子菜单项 MUST NOT 触发条目本身的「打开项目」行为。

#### Scenario: 在资源管理器中显示文件夹
- **WHEN** 用户在某项目的三点子菜单中点击「在资源管理器中显示文件夹」
- **THEN** 系统在操作系统文件管理器中定位并选中该项目的文件夹

#### Scenario: 从项目列表中移除
- **WHEN** 用户在某项目的三点子菜单中点击「从项目列表中移除」
- **THEN** 系统把该项目从注册表移除，左侧清单不再显示它（磁盘上的项目文件不被删除）

#### Scenario: 点三点不触发打开
- **WHEN** 用户点击某条目的三点按钮
- **THEN** 系统仅弹出该条目的子菜单，不打开该项目、不关闭管理项目窗口

### Requirement: 右侧品牌与打开本地项目

管理项目窗口右侧 SHALL 在上方显示 Klarit 品牌标识与应用版本号，下方仅提供一个「打开本地项目」入口。点击「打开本地项目」MUST 让用户选择一个本地目录并按现有导入/打开流程打开它，其后续窗口落点遵循统一打开路由。当所选目录自身非 git、其下含多个 git 子仓时，系统 MUST 直接组建并打开多仓项目（与主窗口导入一致，不再提示需从主窗口侧边栏导入）。版本号 MUST 取自应用的实际版本（`package.json` version）。

#### Scenario: 显示品牌与版本号
- **WHEN** 用户打开管理项目窗口
- **THEN** 右侧上方显示 Klarit 品牌标识与当前应用版本号

#### Scenario: 打开本地项目
- **WHEN** 用户点击右侧的「打开本地项目」并选择一个本地目录
- **THEN** 系统按导入/打开流程打开该目录对应的项目，并按统一窗口路由决定落点

#### Scenario: 打开含多子仓的目录直接组建多仓项目
- **WHEN** 用户在「打开本地项目」中选择一个自身非 git、其下含多个 git 子仓的目录
- **THEN** 系统直接组建多仓项目并打开它，关闭管理项目窗口，不弹任何确认或提示
