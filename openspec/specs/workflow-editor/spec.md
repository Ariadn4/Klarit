# workflow-editor Specification

## Purpose
设置面板内的表单式工作流编辑界面——按字段类型呈现输入控件、阶段列表与节点归属、节点扁平有序列表与拖拽排序、产出与门的编辑、agent 驱动指令的手写/使用文件切换（含 skill 新建/导入/查看），以及校验后保存写回。
## Requirements
### Requirement: 表单式工作流编辑

设置面板 SHALL 提供一个**表单式**工作流编辑界面（非可视化 DAG 画布）。打开某工作流时，其每个可编辑字段 MUST 按字段类型渲染为对应输入控件：

- **文本输入**：显示名、agent 的 prompt、command 的命令行、自动门校验命令、人工门动作按钮的文案与命令、agent 执行配置的额外参数。门把**不带「说明」字段**（命令/按钮文案本身即自描述）。
- **多行文本**：描述、agent 的内联 prompt、产出的内联模板。
- **下拉选择**：节点所属阶段（从阶段列表选）、节点执行者类型、门把类型（自动校验/人工评审）、subworkflow 引用的目标工作流（从库列表选）、**engine 操作**（从引擎内置操作集择一）、**agent 执行配置的工具与模型**（选项来自引擎的 agent 扫描列表，含「跟随全局（不声明）」默认项）。
- **复选**：产出必选/可选。
- **路径输入**：**产出路径**（file 目的地）、可写范围、产出模板「使用文件」时的引用——为带**相对路径校验**的输入控件，实时拒绝绝对路径与 `..`（路径是相对分支/包目录的，保证工作流可移植/可分享），**非 OS 文件选择器**。产出路径另须以 `.md` 结尾（v1 产出即 markdown）。**可写范围默认不呈现输入框**（不声明即表示整条分支可写），用户可按需逐条新增。
- **手写 / 使用文件切换**：`agent` 节点的驱动指令与**产出的模板**均提供「手写 / 使用文件」二选一切换——「手写」呈现多行文本输入（内联文本）；「使用文件」指向工作流包内的一份 markdown 文件。「使用文件」**未选定文件时只展示「新建」「导入」两个按钮**（不展示路径输入框）；**选定后只展示文件名**（不展示相对路径），点击文件名可**查看其内容**，并可移除以重新选择。新建＝编辑器内撰写存为包内文件，导入＝选中外部文件拷入包内（见 `workflow-library` 的包内文件管理）；引用在底层仍以相对包路径记录，但**界面只呈现文件名**。切换控件的当前形态与对应字段的 kind 一致。

编辑界面 MUST 遵循品牌规范（`docs/brand/klarit-brand-system.html`）与 `index.css` 的 `@theme` 设计令牌。

#### Scenario: 字段按类型以对应控件呈现
- **WHEN** 用户打开某工作流进行编辑
- **THEN** 文本字段为文本输入、枚举字段为下拉选择、路径字段为路径输入，且各控件填入当前值

#### Scenario: 切换节点执行者类型
- **WHEN** 用户把某节点的执行者类型从一种切换为另一种
- **THEN** 编辑界面展示该执行者类型对应的驱动指令字段

#### Scenario: engine 操作以下拉择一
- **WHEN** 用户编辑一个 engine 执行者节点的操作
- **THEN** 操作以**下拉框**从引擎内置操作集择一，而非自由文本输入

#### Scenario: 路径输入拒绝非相对路径
- **WHEN** 用户在产出路径、可写范围或产出模板的文件引用输入控件里键入绝对路径或含 `..` 的路径
- **THEN** 编辑界面即时标示该路径非法、阻止保存，直至改为合规的相对路径

#### Scenario: agent 驱动指令在手写与文件间切换
- **WHEN** 用户把某 agent 节点的驱动指令从「手写」切换为「使用文件」（或反向）
- **THEN** 编辑界面相应呈现多行文本输入，或 skill 文件区（未选定文件时仅「新建」「导入」两个按钮、无路径输入框）；保存后 `agent.drivingInstruction` 的 kind 与所选形态一致

#### Scenario: 使用文件时可新建或导入，界面只显示文件名
- **WHEN** 用户在某 agent 节点的驱动指令或某产出的模板选择「使用文件」并新建或导入一份文件
- **THEN** 文件落入工作流包，编辑界面**只显示该文件的文件名**（不显示相对路径），底层引用以相对包路径记录

#### Scenario: 点击文件名查看内容
- **WHEN** 用户点击已选定的文件名
- **THEN** 编辑界面展示该文件的内容

### Requirement: 阶段列表与节点归属

工作流编辑界面 SHALL 把**阶段**呈现为一个可编辑列表：用户能新增阶段、改阶段名、删除阶段；删除阶段时其下节点 MUST 改投到一个仍存在的阶段，不得遗留悬挂的 stageId（且不允许删空到没有阶段）。每个节点 SHALL 通过一个**下拉框选择所属阶段**（选项来自当前阶段列表）。

#### Scenario: 编辑阶段列表
- **WHEN** 用户新增一个阶段或修改阶段名
- **THEN** 阶段列表相应更新，且节点的「所属阶段」下拉随之包含该阶段

#### Scenario: 删除阶段时节点改投
- **WHEN** 用户删除一个仍有节点归属的阶段
- **THEN** 这些节点改投到一个仍存在的阶段，不残留指向已删阶段的引用

### Requirement: 节点有序列表与拖拽排序

工作流编辑界面 SHALL 把节点呈现为一个**扁平的有序列表**（跨阶段），并支持**拖拽改变节点顺序**（基于 @dnd-kit）。用户 SHALL 能新增节点与删除节点。因 v1 为线性工作流，列表顺序即执行顺序，拖拽后的新顺序 MUST 反映为定义中的节点次序。

#### Scenario: 拖拽改变节点顺序
- **WHEN** 用户拖拽某节点到列表的新位置
- **THEN** 节点列表按新位置重排，且该顺序成为工作流定义的节点次序

#### Scenario: 新增与删除节点
- **WHEN** 用户在编辑界面新增或删除一个节点
- **THEN** 节点列表相应增减，变更可被保存

### Requirement: 产出与门的编辑

工作流编辑界面 SHALL 允许为**声明了对应能力的节点**（见「节点设置块按执行者能力呈现」）编辑其**产出**与**门**；对未声明该能力的执行者（如现有的所有 `engine` 操作）不呈现这两块：

- 产出：可新增/删除条目，每条可编辑 **file 目的地路径**（相对路径、须 `.md`，文件名即标识、扩展名即格式）、**模板**、必选/可选。模板只「**不声明 / 从规则库引用**」二选——内容统一住规则库、工作流不嵌入。引用态提供：选已有 `output-template` 条目；**「新建」**（填「存入哪个规则包」+ 名称 + 内容，保存即把条目写进规则库并引用它）；**「编辑」**（当前引用的条目，改其内容写回规则库）。v1 不呈现卡片数据目的地（待需求卡数据模型落地再开）。
- 门：可新增/删除有序门把，每道选类型（自动校验/人工评审），**不带「说明」字段**；并按类型呈现差异字段：
  - **自动校验**：校验提供「**裸命令 / 从规则库引用**」二选——裸命令＝填一条命令（必填）、引用＝选一个 `objective-check` 条目；及可选的**校验目标**——从本节点已声明产出中按路径择取零或多个。
  - **人工评审**：一个**动作按钮**列表，每个按钮含**文案**与**命令**；切到人工评审时**直接预置一行**（文案 + 命令）输入框，可继续增/删，完全空白的行在保存时自动剔除（零按钮亦合法）。

从规则库引用时，编辑界面 SHALL 以下拉/选择器从规则库列出可选条目（按类型过滤——模板处只列 `output-template`、自动校验处只列 `objective-check`），底层以条目 id 记录引用。引用一个本机暂缺的条目不阻塞保存（见 `workflow-definition`）。

#### Scenario: 编辑产出（从规则库引用模板）
- **WHEN** 用户为某节点新增一个产出并填写 file 路径，模板选「从规则库引用」并选一个 `output-template` 条目
- **THEN** 该产出随节点一起保存，模板形态（none/ref）被保留；选 ref 时记录所选条目 `{packId, itemId}`

#### Scenario: 模板「新建」把内容写进规则库再引用
- **WHEN** 用户在产出模板的引用态点「新建」，选存入哪个规则包、填名称与内容、保存
- **THEN** 该内容作为一个 `output-template` 条目写进所选规则包（经 `rule-pack-model` 校验），编辑界面随即引用它（工作流不内嵌该内容）

#### Scenario: 编辑自动校验门把（裸命令或引用）
- **WHEN** 用户新增一道自动校验门把，校验选「裸命令」填写命令、或选「从规则库引用」选一个 `objective-check` 条目，并（可选）勾选若干校验目标
- **THEN** 该门把连同校验形态（inline/ref）与目标随节点一起保存

#### Scenario: 编辑人工评审门把的动作按钮
- **WHEN** 用户把门把切到人工评审
- **THEN** 编辑界面**直接呈现一行动作按钮输入（文案 + 命令）**，填写后随门把保存、抛出决策时据此渲染

#### Scenario: 切换门把类型呈现对应字段
- **WHEN** 用户把某门把类型在「自动校验」与「人工评审」间切换
- **THEN** 编辑界面相应呈现「校验（裸命令/引用）+ 目标」或「动作按钮列表（预置一行文案+命令）」字段，且不呈现任何「说明」输入

#### Scenario: 规则库引用按类型过滤可选条目
- **WHEN** 用户在产出模板处或自动校验处选择「从规则库引用」
- **THEN** 选择器仅列出对应类型的条目（模板处只列 `output-template`、校验处只列 `objective-check`）

#### Scenario: 无产出/门能力的执行者不呈现两块
- **WHEN** 用户打开一个执行者为现有 `engine` 操作的节点详情
- **THEN** 编辑界面不呈现产出与门两块（这些操作不交付文档、不跑客观门）

### Requirement: 保存写回工作流

编辑界面 SHALL 提供保存操作，把当前编辑结果写回该工作流的 YAML（经 `workflow-library` / `workflow-definition` 的校验）。校验失败 MUST 阻止保存并在界面提示原因；保存成功后列表与激活选择器 MUST 反映最新显示名。

#### Scenario: 保存合法编辑
- **WHEN** 用户保存一份通过校验的编辑
- **THEN** 系统写回该工作流 YAML，界面反映最新内容

#### Scenario: 保存非法编辑被阻止
- **WHEN** 用户尝试保存一份未通过校验的编辑（如非法产出路径）
- **THEN** 系统阻止保存并在界面提示失败原因，磁盘上的工作流不被改动

### Requirement: agent 执行配置的编辑

工作流编辑界面 SHALL 允许为 `agent` 执行者节点编辑可选的**执行配置**：**工具**与**模型**以下拉择取（选项来自引擎的 agent 扫描列表，且含一个「跟随全局（不声明）」默认项），**额外参数**以文本输入。这些控件 SHALL 只在执行者类型为 `agent` 时呈现，且不声明任何字段时该节点跟随全局设置。

#### Scenario: 编辑 agent 工具与模型
- **WHEN** 用户在某 agent 节点的执行配置选择工具/模型并填写额外参数
- **THEN** 这些字段随节点一起保存

#### Scenario: 不声明执行配置跟随全局
- **WHEN** 用户把某 agent 节点的工具/模型保持为「跟随全局（不声明）」
- **THEN** 该字段不写入声明、保存后该节点跟随全局设置

### Requirement: 编辑工作流的「新建需求」分解 prompt

工作流编辑界面 SHALL 为每个工作流提供其**「新建需求」分解 prompt** 的编辑入口（工作流级，区别于各节点的 agent prompt）。该编辑 MUST 提供与 agent 节点驱动指令一致的「**手写 / 使用文件**」二选一切换：

- **手写**：呈现多行文本输入，存为 `inline` 形态。
- **使用文件**：指向工作流包内一份 markdown skill 文件；**未选定文件时只展示「新建」「导入」两个按钮**（不展示路径输入框），**选定后只展示文件名**、点击文件名可查看内容、可移除以重新选择——与节点 prompt 的「使用文件」体验完全一致（复用既有包内文件管理控件）。

该「新建需求」prompt 为**可选**：用户可不声明（保存后该工作流无专属分解 prompt）。保存 MUST 经 `workflow-definition` 的校验；非法（如 file 形态路径越界）MUST 阻止保存并提示原因。编辑界面 MUST 遵循品牌规范（`docs/brand`）与 `index.css` 的 `@theme` 设计令牌、支持深浅双主题、仅用语义令牌。

#### Scenario: 手写新建需求 prompt 并保存
- **WHEN** 用户在某工作流的「新建需求」prompt 选「手写」、填入文本并保存
- **THEN** 该 prompt 以 `inline` 形态随工作流保存，读回时文本保留

#### Scenario: 使用文件时新建或导入 skill
- **WHEN** 用户为「新建需求」prompt 选「使用文件」并新建或导入一份 skill 文件
- **THEN** 文件落入工作流包，编辑界面只显示文件名（不显示相对路径），底层以相对包路径记录，体验与节点 prompt 一致

#### Scenario: 不声明新建需求 prompt
- **WHEN** 用户不为某工作流声明「新建需求」prompt 并保存
- **THEN** 保存成功，该工作流无专属分解 prompt（分解时回落全局默认分解 skill）

#### Scenario: 非法新建需求 prompt 阻止保存
- **WHEN** 用户为「新建需求」prompt 选「使用文件」并键入越界路径（绝对路径或含 `..`）
- **THEN** 编辑界面标示该路径非法、阻止保存，直至改为合规相对路径

### Requirement: 查看 agent 节点的完整 prompt

工作流编辑界面的**节点详情** SHALL 为 `agent` 执行者节点提供一个「**查看完整 prompt**」入口：节点详情顶栏（与保存同一行）呈现一个 **file-text 图标按钮**。该按钮 MUST **仅在执行者类型为 `agent`** 时呈现；其它执行者类型（engine / command / subworkflow）与其它详情页（如建议类型详情）MUST NOT 呈现它。

点击该按钮 SHALL 打开一个**只读模态**，展示该节点经 `agent-prompt-assembly` 拼装出的**完整 prompt**（回复语言 + 宪法 + 节点 prompt + 需求卡占位 + 可写范围 + 产出/模板）。预览 MUST 反映**当前正在编辑的节点状态**（含尚未保存的改动），使用户能边写边看其在全局上下文里的最终形态。节点 prompt 为「使用文件」形态时，预览 MUST 先读出 skill 文件内容再拼；读取失败时该层 MUST 显示错误提示而非整体崩溃。

模态 MUST 明确提示需求卡为运行期注入的占位、执行配置不在 prompt 文本内，避免用户误读预览为「agent 收到的全部」。预览为只读，MUST NOT 在模态内编辑 prompt。该界面 MUST 遵循品牌规范（`docs/brand`）与 `index.css` 的 `@theme` 设计令牌、支持深浅双主题、仅用语义令牌（模态暗罩除外）。

#### Scenario: agent 节点详情呈现查看按钮
- **WHEN** 用户打开一个 `agent` 执行者节点的详情
- **THEN** 节点详情顶栏（与保存同行）呈现一个 file-text 图标按钮

#### Scenario: 非 agent 节点不呈现查看按钮
- **WHEN** 用户打开一个 engine / command / subworkflow 节点的详情
- **THEN** 顶栏不呈现该 file-text 按钮

#### Scenario: 点击查看完整 prompt
- **WHEN** 用户在某 agent 节点点击该按钮
- **THEN** 打开只读模态，展示经 `agent-prompt-assembly` 拼装的完整 prompt（含需求卡占位）

#### Scenario: 预览反映未保存的编辑
- **WHEN** 用户改动了某 agent 节点的 prompt / 可写范围但尚未保存，随即点击查看
- **THEN** 预览呈现当前编辑中的内容（反映未保存改动）

#### Scenario: 使用文件形态预览读取内容
- **WHEN** 某 agent 节点的 prompt 为「使用文件」形态且用户查看完整 prompt
- **THEN** 预览先读出 skill 文件内容再拼入；读取失败时该层显示错误提示、其它层照常呈现

### Requirement: 节点设置块按执行者能力呈现

节点详情对「**可写范围**」「**产出**」「**检查（门）**」三块的呈现 SHALL 由**当前执行者的能力**驱动，而非无条件常显。某块当且仅当当前执行者声明需要该能力时呈现；不呈现的块不渲染其任何控件、其对应字段保持空（不写入定义）。能力按执行者类型解析：

- `agent`：三块**全部呈现**（agent 会写代码/交付文档、需可写范围与门）。
- `engine`：按**所选具体操作**的能力声明（见 `workflow-definition`「引擎内置操作的能力声明」）**逐块**呈现——某操作的某项能力为否则隐藏对应块；**未选操作**时三块全隐。当前 4 个引擎操作三项能力皆否，故其下三块均不呈现。
- `subworkflow`：三块**均不呈现**。子工作流节点只是**委派**给另一条工作流执行，自身不写代码、不交付文档、不跑门——可写范围 / 产出 / 检查由**被调工作流内部各节点**各自声明与承担，在调用点声明无归属对象。
- `command`：三块**全部呈现**（任意 CLI 命令可能写盘、产出文件、受门约束）。

未来若新增任一项能力为真的引擎操作，编辑界面 MUST 据其能力声明自动呈现对应块，无需改动界面的显隐逻辑。

#### Scenario: agent 节点三块全显
- **WHEN** 用户打开一个 `agent` 执行者节点的详情
- **THEN** 可写范围、产出、检查三块均呈现并可编辑

#### Scenario: 现有引擎操作隐藏三块
- **WHEN** 用户打开一个 `engine` 执行者节点并选中 `create-branch`（或其它现有引擎操作）
- **THEN** 可写范围、产出、检查三块均不呈现

#### Scenario: 未选引擎操作时隐藏三块
- **WHEN** 用户把节点执行者切到 `engine` 但尚未选择具体操作
- **THEN** 可写范围、产出、检查三块均不呈现

#### Scenario: 切换引擎操作按能力更新显隐
- **WHEN** 用户在 `engine` 节点把所选操作改为一个声明了某项能力为真的操作
- **THEN** 编辑界面据该操作的能力声明自动呈现对应的块（能力为否的块仍隐藏）

#### Scenario: 子工作流节点隐藏三块
- **WHEN** 用户打开一个 `subworkflow` 执行者节点的详情
- **THEN** 可写范围、产出、检查三块均不呈现（这些由被调工作流内部节点承担）

### Requirement: command 节点的多命令列表编辑

`command` 执行者节点的设置块 SHALL 把命令呈现为**一条以上命令行的列表**(对应 `workflow-definition` 的 `commands: CommandSpec[]`),而非单一命令输入。每行含:**命令行**(必填)、可选**标签**、可选**前置检查命令**、可选**超时(秒)**。编辑器 SHALL 在打开一个 `command` 节点时**至少预置一行**,允许用户**增行/删行**;完全空白的行(命令行为空)在保存时**自动剔除**;剔除后 MUST **至少保留一条命令行非空**,否则按 `workflow-definition` 校验(`commands` 非空)拒绝保存并提示。

#### Scenario: command 节点呈现多命令列表并可增删
- **WHEN** 用户打开一个 `command` 执行者节点的详情
- **THEN** 呈现命令行列表(至少预置一行),可增行/删行,每行含命令行 + 可选标签/前置检查/超时

#### Scenario: 空白命令行保存时剔除
- **WHEN** 用户在多命令列表里留有若干完全空白的行并保存
- **THEN** 空白行被自动剔除,仅非空命令随节点保存;若剔除后无任何命令则保存失败并提示至少需一条命令

#### Scenario: 多命令往返保持
- **WHEN** 用户为一个 `command` 节点填写两条命令(各含命令行与可选字段)并保存后重开
- **THEN** 两条命令及其字段完整回显在列表中

### Requirement: command 节点的前置检查命令编辑与软提示

`command` 执行者节点的多命令列表中,**每一行命令** SHALL 各提供一个可选**前置检查命令**输入(对应该行 `CommandSpec` 的 `check` 字段),并在其旁呈现一段**软提示**,引导作者为不幂等命令补上前置检查,以避免中断恢复时重复执行。该提示为**纯引导**——编辑器 MUST NOT 强制要求填写前置检查(系统无法可靠判别命令是否幂等),仅在用户填写后按 `workflow-definition` 的结构校验(声明则非空)参与保存校验。

软提示文案 SHALL 以「非幂等命令(跑一次生效后重跑会重复或产生副作用,如数据库迁移、版本号自增、发送通知等)建议加前置检查」为意,**不以部署/发布为例**(该类引导走引擎操作)。提示文案为 i18n、随语言切换。

#### Scenario: 每行命令呈现前置检查输入与提示
- **WHEN** 用户打开一个 `command` 执行者节点的详情
- **THEN** 每行命令呈现「命令」与可选「前置检查命令」输入,且前置检查旁有引导软提示

#### Scenario: 前置检查为可选不阻塞保存
- **WHEN** 用户未填写某行命令的前置检查即保存一个 `command` 节点
- **THEN** 不因缺少前置检查而拒绝保存(该字段可选)

#### Scenario: 填写空白前置检查被校验拦截
- **WHEN** 用户为某行命令的前置检查输入了空白内容并保存
- **THEN** 保存校验失败并提示前置检查命令不可为空(对齐 `workflow-definition` 校验)

### Requirement: 每条命令的可选超时编辑

工作流编辑器 SHALL 为每一处可执行命令提供一个可选**超时(秒)**输入:`command` 节点多命令列表的**每行命令**处、每道客观门把处、每个人工门把动作按钮处各有其独立的超时输入。该输入为可选(留空=无超时);填写时其值 MUST 经 `workflow-definition` 校验(正数)参与保存。编辑器 MUST NOT 设任何默认超时(全局默认无超时)。

#### Scenario: 命令与客观门可各设超时
- **WHEN** 用户编辑一个 `command` 节点某行命令及其客观门把
- **THEN** 该行命令处与该客观门把处各有独立可选超时输入,填写的正数值随定义保存、留空即无超时

#### Scenario: 超时留空即无限制
- **WHEN** 用户不填某命令的超时即保存
- **THEN** 该命令视为无超时,保存不被阻塞


### Requirement: 工作流编辑器按语言下拉编辑显示文本

工作流编辑器 SHALL 在顶栏提供一个**语言下拉**（列出软件受支持语言 ∪ 该定义已带的开放语言键），选中哪个语言，工作流名/描述、阶段名、节点名等**可翻显示文本**就以**单一输入框**编辑该语言的值；切换下拉即把这些字段切到对应语言（语言再多也只占一个下拉、不横向膨胀）。输入框真值 MUST 为 `field[所选语言]`（可能空）——当前语言为空时 MUST 以其它语言的回退值作**灰色占位**（仅提示、不预填），绝不把回退值当真值填入，避免保存时把别的语言复制进当前语言。某语言某字段留空 MUST 表示该语言未翻译、不写入该语言键（不写空串）。节点进入详情编辑时，其顶栏 SHALL 同样提供该语言下拉。只读引用（如所属阶段下拉、subworkflow 目标、节点列表行）按当前界面语言解析显示。

#### Scenario: 语言下拉切换编辑语言
- **WHEN** 用户在工作流编辑器把顶栏语言下拉从 `zh` 切到 `en`
- **THEN** 工作流名、各阶段名、节点名的输入框从显示 `zh` 值切换为显示 `en` 值（同一输入框、不新增栏）

#### Scenario: 节点名按所选语言单栏编辑
- **WHEN** 用户进入某节点详情、语言下拉选 `en`，在节点名输入框填入英文
- **THEN** 保存后该节点名的语言表含 `en` 条目；其它语言条目不受影响

#### Scenario: 结构字段与只读引用不受编辑语言影响
- **WHEN** 切换编辑语言
- **THEN** 引擎操作、命令、路径等结构字段不变；所属阶段/目标工作流等只读下拉按界面语言显示名称

### Requirement: 节点列表对含门节点显示门徽标

工作流编辑器的**节点列表**(每行一个节点)SHALL 对**挂了门的节点**显示一个**门徽标**,按门类区分 `manual`/`auto`/`external`,使人工评审/自动校验/外部门等检查点**在列表层一眼可见**,而无需逐个点开节点。徽标 SHALL 从 `node.gate[]` 派生(有几类显示几类),纯展示、不改数据模型,配色用语义令牌(深浅两套)。无门的节点不显示徽标。

#### Scenario: 挂了 manual 门的节点显示徽标

- **WHEN** 节点列表渲染一个 `node.gate` 含 `manual` 门的节点
- **THEN** 该行显示可辨识的门徽标(标出 manual),用户不必点开即知此处有人工检查点

#### Scenario: 多类门都标出

- **WHEN** 某节点同时挂了不同类的门(如 auto + manual)
- **THEN** 徽标按门类分别标出

#### Scenario: 无门节点不显示徽标

- **WHEN** 节点没有任何门(`node.gate` 空/缺)
- **THEN** 该行不显示门徽标

### Requirement: archive-docs 节点详情展示/编辑归档文档配置

工作流编辑器的**节点详情**视图,对**引擎操作为 `archive-docs`** 的节点 SHALL 展示并允许编辑其 `executor.archiveDocs` 归档文档配置——每条为 `{ path, kind: 'dynamic' | 'snapshot' }`:一行一条,含路径输入 + 动态/快照选择,可增删。这样 author 产出的(或用户手改的)归档清单**可见可改**。非 archive-docs 节点不显示该块。空配置时显示"尚未指定要归档的文档"之类提示(**不提登记表**——已不再回落)。说明文案讲清动态/快照规则。配色用语义令牌。

#### Scenario: archive-docs 节点显示归档文档清单

- **WHEN** 在节点详情打开一个引擎操作 `archive-docs` 的节点,其 `executor.archiveDocs` 有若干 `{path,kind}`
- **THEN** 逐条展示路径 + 动态/快照,且可编辑(改路径/切 kind/增删)

#### Scenario: 非 archive-docs 不显示该块

- **WHEN** 打开一个非 archive-docs 节点
- **THEN** 不显示归档文档清单块

#### Scenario: 空配置给提示

- **WHEN** archive-docs 节点无 `executor.archiveDocs`
- **THEN** 显示空态提示「尚未指定要归档的文档」(不提登记表),而非什么都不显示
