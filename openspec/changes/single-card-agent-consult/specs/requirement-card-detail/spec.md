## ADDED Requirements

### Requirement: 卡详情面板的单需求 agent 咨询区

需求卡详情面板 SHALL 新增一个**单需求 agent 咨询区**，作为用户跟该卡常驻只读单需求 agent 多轮对话的入口，与既有「单卡决策区」并列。咨询区 MUST：

- **一卡一个会话、不可多开**：打开某卡始终续上**同一条**该卡会话（见 `single-card-agent`），不提供「新建会话」；与全局对话面板物理隔离、互不串扰。
- **多轮对话**：用户发自由意图/问题，经单需求 agent 三岔作答——**查进度**（读活现状+断点+溯源+分支 diff 的只读作答）、**本卡干预提议**、**上抛塑造需求的 ops 提案**；纯咨询轮只显回复、空回复不留占位（复用全局对话消息行为）。
- **复用组件**：消息列表/输入/复制、以及 ops 提案审阅（`card-ops-review-apply`）复用全局对话面板与决策面板既有组件与 patterns。
- **清空对话**：咨询区提供「清空对话」入口，经**二次确认**（内联，不用原生弹窗）后清空该卡会话消息与续接（见 `single-card-agent`），回到空态。
- **本卡干预确认流**：agent 提议的干预呈现为可执行动作——**暂停/恢复可直接执行**（无损）；**倒回节点 K / 就地注入 / 结构性改动**为破坏性，MUST 经**二次确认**后才经引擎（`engine.reenter`/`engine.inject`）或 store 执行；agent 只提议、渲染层不持有运行生命周期。
- **上抛 ops 提案审阅**：塑造需求上抛得到的 ops 提案在咨询区内呈现，经 `applyOps` 审阅（逐 op 校验、破坏性二次确认）确认后应用，随后刷新看板。

咨询区 MUST 遵循 `docs/brand` 与设计令牌（仅语义令牌、深浅双主题）。

#### Scenario: 打开卡续上其单需求 agent 会话

- **WHEN** 用户打开一张卡的详情面板咨询区
- **THEN** 续上该卡既有单需求 agent 会话（无「新建会话」），全局对话会话不出现在此

#### Scenario: 查进度得只读作答

- **WHEN** 用户在咨询区问该卡当前进度
- **THEN** agent 据只读上下文（活现状/断点/溯源/分支 diff）作答，不产干预、不留空占位

#### Scenario: 破坏性干预经二次确认

- **WHEN** agent 提议「倒回到节点 K 并注入新指令」，用户在咨询区确认
- **THEN** 经 `engine.reenter` 执行重入前向修复；未确认前不执行；暂停/恢复类无损干预可直接执行

#### Scenario: 上抛 ops 提案在咨询区审阅应用

- **WHEN** 用户说「还要加个需求 X」，上抛得到 create ops 提案
- **THEN** 提案在咨询区内呈现，经 `applyOps` 审阅确认后应用，看板出现新卡

#### Scenario: 咨询区遵品牌令牌深浅双主题

- **WHEN** 在深色或浅色主题下打开咨询区
- **THEN** 其配色仅用语义令牌、两套主题都正确翻色

#### Scenario: 清空对话须二次确认

- **WHEN** 用户点「清空对话」并确认
- **THEN** 该卡会话消息清空、回到空态；未确认前不清空

### Requirement: 咨询区消息底部操作与打断思考

咨询区 SHALL 在每条消息底部提供操作按钮，**顺序与全局对话一致**（复制 → 编辑 → 重试）：

- **所有消息**：始终有「复制」（复制整条消息文字——agent 消息含其回复与提案/干预的可读描述），复用既有剪贴板通道（`copyText`）。
- **仅最新一条用户消息**：另有「编辑」（把该消息文字回填输入框、并移除该轮）与「重试」（丢弃该轮 agent 回复、按本会话选型重跑该条用户意图，替换而非追加）。agent 消息只有「复制」。

咨询区 SHALL 允许**打断进行中的咨询轮**：当某轮咨询正在进行（agent 思考/产出）时，提供「停止」入口，点击后**中止该卡正在跑的咨询 agent**，运行回到可输入态（该轮不再追加内容，或只保留已产出的部分），不报错、不卡死。

#### Scenario: 复制任一消息

- **WHEN** 点击某条消息底部的「复制」
- **THEN** 该消息文字写入系统剪贴板

#### Scenario: 编辑与重试仅在最新用户消息

- **WHEN** 查看历史消息
- **THEN** 只有最新一条用户消息有「编辑」「重试」，其余消息与 agent 消息只有「复制」

#### Scenario: 编辑最新用户消息

- **WHEN** 点最新用户消息的「编辑」
- **THEN** 其文字回填输入框、该轮从对话移除，供修改后重发

#### Scenario: 重试最新用户消息

- **WHEN** 点最新用户消息的「重试」
- **THEN** 丢弃该轮 agent 回复、按本会话选型重跑该条用户意图，用新回复替换

#### Scenario: 打断进行中的咨询

- **WHEN** 某轮咨询进行中，用户点「停止」
- **THEN** 该卡正在跑的咨询 agent 被中止，咨询区回到可输入态，不报错

### Requirement: 详情页为侧抽屉，询问 Agent 为底部可开合抽屉

需求卡详情 SHALL 呈现为**从右侧推挤看板的侧抽屉**（**无遮罩**——看板让位、仍可见；顶部提供关闭入口 ✕），而非居中蒙层弹窗。抽屉内自上而下为：头部（标题/状态/类型/关闭）+ **任务内容区**（描述、运行控制、命令推进、单卡决策、前台/后台输出，可滚动）。

「询问 Agent」咨询区 SHALL 呈现为抽屉**底部的可开合抽屉**：

- **默认折叠**：只露一条**把手栏**（含「询问 Agent」标题、**清空对话按钮**、展开/收起控件）与**输入框**；任务内容区正常可见可操作。
- **展开触发**：用户在输入框**发送问题**，或**点把手/拉起**，底部抽屉 SHALL 向上展开，**覆盖**任务内容区显示对话（消息气泡、建议、提案），输入框仍钉在底部。
- **收起**：点把手（收起控件）SHALL 收回折叠态，任务内容区原样恢复。
- **清空对话按钮** SHALL 明确呈现在把手栏（图标 + 文案），点击经内联二次确认后清空（见「清空对话须二次确认」）。

侧抽屉与底部抽屉 MUST 遵循 `docs/brand` 与设计令牌（仅语义令牌、深浅双主题）。

#### Scenario: 详情为推挤式侧抽屉、无遮罩

- **WHEN** 打开一张卡的详情
- **THEN** 详情从右侧滑入、看板让位（无黑色遮罩），顶部有关闭入口

#### Scenario: 询问 Agent 默认折叠只露输入

- **WHEN** 打开详情、未与 Agent 交互
- **THEN** 底部只显示把手栏（含清空按钮）与输入框，任务内容区完整可见

#### Scenario: 发送或拉把手即展开覆盖任务内容

- **WHEN** 用户在输入框发送问题，或点把手拉起
- **THEN** 底部抽屉向上展开、覆盖任务内容区显示对话；点把手收起后任务内容区恢复
