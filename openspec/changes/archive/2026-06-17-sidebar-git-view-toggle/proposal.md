## Why

侧边栏目前只能看「项目目录文件树」，但 Klarit 的用户做的是需求驱动的多仓 + 多分支开发，编排 agent 时经常要看「现在在哪个成员仓、哪个分支、有哪些 worktree」。把 git 维度塞进文件树里会让两种心智模型互相打架，所以需要在侧边栏顶部给一个明确的视图切换：要么看文件、要么看 git。

## What Changes

- 侧边栏顶部新增一行视图切换区，含两个 icon：文件夹 icon（文件树视图）与 git icon（git 视图）。点击在两态间切换，**默认选中文件夹（文件树视图）**，与现状一致。
- 新增 **git 视图**（**只读预览器**，类似资源管理器，不改 git 状态/工作区）：顶部展示「当前成员仓名 + 当前选中分支」（形如 `🖥 VibePM  ⑂ main`），下方展示该分支对应 **worktree 目录的文件树**。
- 成员仓名可点击：弹出该项目全部成员仓列表，选择即切换当前成员仓（换看哪个仓）。
- 分支名可点击：弹出该成员仓的**本地分支**列表，选择即把下方文件树切到该分支对应的 worktree 目录——**纯切换显示目录，不执行 git checkout/switch，与未提交改动无关**。
- 视图切换状态（文件树 / git）以及 git 视图下选中的成员仓与分支，按窗口持久化，下次打开恢复。

## Capabilities

### New Capabilities
- `sidebar-git-view`: 侧边栏的 git 视图——顶部成员仓选择器 + 分支选择器，下方对应 worktree 文件树；以及成员仓/分支的切换交互与持久化。

### Modified Capabilities
- `app-shell-sidebar`: 侧边栏顶部新增「文件树 / git」视图切换（两个 icon，默认文件树）；原「当前项目目录文件树」成为文件树视图下的展示，切换状态按窗口持久化。

## Impact

- 渲染层：侧边栏组件（顶部新增视图切换条、新增 git 视图子树与成员仓/分支选择器弹层）；新增/扩展 zustand store 记录视图模式、当前成员仓、当前分支。
- 主进程：需要**只读** git 查询能力——列出成员仓本地分支、列出/解析 worktree 及其目录路径；通过 IPC 暴露给渲染层。不新增任何 git 写操作。复用 `multi-repo-project` 已有的成员仓模型与 git 检测。
- 持久化：视图模式与 git 视图选择项纳入按窗口持久化的状态。
- 不改动文件树视图的现有行为（单仓直接展示、多仓按成员仓分组）。
