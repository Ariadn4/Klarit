## MODIFIED Requirements

### Requirement: 合并分支(冲突即回到干净态)

系统 SHALL 提供一个**合并**原语:把来源分支合并进目标分支。**默认**当合并产生**冲突**或被打断而留下在途合并(`MERGE_HEAD` 存在)时,该原语(或其上层 ensure)MUST 能**中止合并**(`git merge --abort`)使工作树回到合并前的干净态,并以结构化结果报「冲突/已中止」,**不留半合并的脏索引**。当来源已并入目标(无可合并)时,MUST 报「已是最新」而非报错。

该原语 SHALL 额外支持一个**「保留冲突态」模式**(可选参数):启用时,冲突**不立即 abort**——保留 `MERGE_HEAD` 与工作区冲突标记、以结构化结果报「冲突」返回,供上层交给 heal agent 就地解决(见 `node-failure-heal`)。此模式下的**延迟中止**由上层负责:上层在 heal 失败/超限时 MUST 补 `git merge --abort`(并按需重置分支)回到干净态,绝不遗留半合并脏索引。**默认模式(不启用该参数)行为不变**——冲突仍即时 abort。

冲突判定 MUST 以**未合并条目**(`git ls-files -u` 非空)为准,而非仅匹配 git 的英文提示文案——以兼容 git 输出本地化、以及合并因其它原因失败但确有冲突残留的情形;文案匹配仅作辅助兜底。合并命令**非零退出但无未合并条目且文案不含冲突关键字**时,MUST 归为 `error`(而非误报 conflict)。

#### Scenario: 无冲突合并成功
- **WHEN** 把一个与目标无冲突的来源分支合并进目标
- **THEN** 合并完成,结果标记成功

#### Scenario: 默认模式冲突即回到干净态并上报
- **WHEN** 以默认模式把一个与目标冲突的来源分支合并进目标
- **THEN** 合并被中止、工作树回到合并前干净态,结果标记「冲突」(供上层抛固定决策)

#### Scenario: 保留冲突态模式冲突时不 abort
- **WHEN** 以「保留冲突态」模式把一个与目标冲突的来源分支合并进目标
- **THEN** 原语**不** abort、保留 `MERGE_HEAD` 与工作区冲突标记,结果标记「冲突」返回,供上层交 heal agent 解决

#### Scenario: 冲突判定以未合并条目为准(语言无关)
- **WHEN** 合并失败且 `git ls-files -u` 有未合并条目(无论 git 文案是何种语言、是否为空)
- **THEN** 结果标记「冲突」,不因文案不匹配英文关键字而误报 `error`

#### Scenario: 已合并则报已是最新
- **WHEN** 来源分支已并入目标
- **THEN** 结果标记「已是最新」(幂等 no-op),不报错
