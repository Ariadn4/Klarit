## ADDED Requirements

### Requirement: 引擎/命令节点技术失败路由到临时 heal agent

引擎处理**引擎节点**与**命令节点**的**技术性失败**时,SHALL 在抛人工决策**之前**先尝试**自动自愈**:拉起一个**临时读写 heal agent**(复用 agent 执行器)在该失败所在的**卡工作区**改代码 / 解冲突,引擎随后**确定性提交**并**幂等重跑**该失败操作做验证;收敛则继续、不打扰人。可路由到 heal 的技术失败**仅**三种:

- 引擎 `merge-branch` 的**合并冲突**(`outcome==='conflict'`);
- 命令节点**主命令非零退出**;
- 命令节点的**客观校验门报错**(非零退出)。

其余失败 MUST **不**路由 heal,保持既有归宿不变:push 非快进/无远端/认证、delete 未合并、worktree 占用/脏、命令/门**超时**、**engine 节点**的客观门报错、以及自动类(link-env 缺失跳过、delete-remote 跳过、瞬时锁重试)。heal MUST **限次**;超限 MUST **回落到该失败既有的人工前进式决策**(文案与选项不变)。

#### Scenario: 合并冲突先 heal 而非直接抛人工
- **WHEN** 引擎节点 `merge-branch` 对某成员仓合并回主线时冲突,且 heal 可用、未超限
- **THEN** 引擎拉起临时 heal agent 尝试自愈,而非直接抛「放弃合并,跳过该节点」决策

#### Scenario: 命令非零退出先 heal
- **WHEN** 命令节点主命令非零退出,且 heal 可用、未超限
- **THEN** 引擎拉起临时 heal agent 改代码,而非直接抛「命令执行失败」决策

#### Scenario: 非技术失败不路由 heal
- **WHEN** 引擎节点 push 非快进、或 delete 未合并、或命令超时
- **THEN** 引擎按既有归宿处理(人工决策 / 自动),不拉起 heal agent

#### Scenario: 超限回落到既有人工决策
- **WHEN** 某技术失败的 heal 达到重试上限仍未收敛
- **THEN** 引擎回落到该失败原本的人工前进式决策(合并冲突回「放弃合并,跳过该节点」、命令失败回「重试/跳过本节点」),文案与选项不变

### Requirement: heal 超限回落决策携带 AI 尝试详情

heal 超限回落人工决策时,决策的**用户可读原因**(`reason`)MUST 在原失败详情(如冲突文件清单 / 命令输出)之外,附上**「AI 已自动尝试解决几次、最后一次失败原因」**——最后一次失败原因优先取 agent 握手 detail,否则取 agent 最近输出尾部(能暴露连接失败 / API 报错等真因)。未配置可用 AI(无默认 agent)时,原因 MUST 说明「未配置 AI、无法自动解决」。消费方(决策面板)SHALL 把原因展示在选项之前。

#### Scenario: 回落决策原因含 AI 尝试次数与真实报错
- **WHEN** 合并冲突 heal 因 agent 连不上 API 连续失败 3 次后回落人工
- **THEN** 决策原因含冲突文件详情 + 「AI 已自动尝试解决 3 次仍未成功,最后一次失败原因:<agent 的连接/API 报错>」

#### Scenario: 无可用 AI 时原因说明未配置
- **WHEN** 未配置默认 agent、合并冲突无法自动 heal 而回落人工
- **THEN** 决策原因说明「未配置可用的 AI,无法自动解决,请手动处理」

### Requirement: 合并冲突在卡分支上解、解完快进合回主线

合并冲突的自愈 SHALL **不在主线上解、也不新建隔离目录**,而在**卡自己已隔离的工作区**里进行:引擎在卡工作区把**主线并进卡分支**(`git merge <主线>`,以**保留冲突态**模式合并、不立即 abort),让冲突显现在卡分支这边;heal agent 就地解冲突;解完后卡分支已消化主线,引擎再把卡分支**快进合回主线**(此时无冲突)。整个过程主线 MUST 全程不被改动——heal 失败时引擎 MUST 把卡分支**重置回并主线前的状态**并 abort 在途合并,使主线与卡分支都回到干净态。

#### Scenario: 主线并进卡分支后在卡工作区解冲突
- **WHEN** 卡分支合并回主线冲突且进入 heal
- **THEN** 引擎在卡工作区以保留冲突态模式把主线并进卡分支,heal agent 在卡工作区解冲突,主线未被改动

#### Scenario: 解完快进合回主线
- **WHEN** heal agent 解完冲突、引擎确定性提交后卡分支已含主线
- **THEN** 引擎把卡分支快进合回主线(无冲突),该合并操作收敛

#### Scenario: heal 失败重置回干净态不脏主线
- **WHEN** 合并冲突 heal 超限
- **THEN** 引擎重置卡分支回并主线前状态、abort 在途合并,主线与卡分支均干净,再回落人工「放弃合并,跳过该节点」

### Requirement: 多仓逐仓 heal、各仓独立

当一个引擎 `merge-branch` 节点在多个成员仓扇出时,冲突是**逐仓**的:引擎 SHALL **哪个成员仓冲突就为哪个仓拉一个 heal agent**(在各自卡工作区),各仓 heal **独立**——独立的重试计数、独立的收敛/超限判定,互不影响。已干净合并的成员仓照常推进(其幂等性由「是否已是主线祖先」探测兜);某成员仓 heal 超限则以带该成员标识的失败抛人工决策,不阻断对其余成员的处理判定。

#### Scenario: 只对冲突的成员仓拉 heal
- **WHEN** 卡涉及成员 A、B,合并回主线时仅 B 冲突
- **THEN** 引擎仅为 B 拉 heal agent,A 直接干净合并推进

#### Scenario: 逐仓计数互不影响
- **WHEN** 成员 B 的 heal 已重试若干次
- **THEN** 该计数只属 `(该节点, B)`,不影响其它成员仓的 heal 计数

### Requirement: heal agent 只改不提交、引擎确定性提交并幂等重跑验证

heal agent MUST **只**把冲突文件改到无冲突 / 把代码改到失败操作能通过,**不自己提交**——提交由**引擎**确定性执行(对齐可写范围越界还原「不靠 agent 自觉」的红线)。引擎在 heal agent 退出后 SHALL:

- **合并冲突**:先校验**无残留冲突标记**(未合并条目为空),再在卡工作区提交(在途合并存在故成为一次合并提交),然后**重跑合并判定**(卡分支是否已是主线祖先)确认收敛。
- **命令失败**:提交范围内改动,再**重跑那条命令**;退出码 0 即收敛(命令节点客观门失败则**重跑那道门**)。

验证 MUST 以**客观事实**为准(冲突标记清空 / 命令或门退 0),MUST NOT 以 agent 自述为准。若校验未过(仍有冲突标记 / 命令仍非零),计一次失败,重试或超限。

#### Scenario: 引擎提交而非 agent 提交
- **WHEN** heal agent 解完冲突退出
- **THEN** 引擎校验无残留冲突标记后自己提交这次合并,commit 由引擎身份完成

#### Scenario: 命令 heal 后重跑命令验证
- **WHEN** 命令失败的 heal agent 改完代码、引擎提交后
- **THEN** 引擎重跑该命令,退 0 才算收敛,仍非零则计一次失败

#### Scenario: 冲突标记未清视为未收敛
- **WHEN** 合并 heal agent 退出但工作区仍有未解决的冲突标记
- **THEN** 引擎判定未收敛,计一次失败(重试或超限),不提交半解决的合并

### Requirement: heal 限次与持久化计数

heal 的重试计数 SHALL 按 **`(节点, 成员仓)`** 累计(命令节点退化为按节点),复用 agent 自愈的重试上限,并**持久化到运行断点**——关软件重开后计数**不清零**;该失败最终收敛后其计数清零。超限即回落既有人工决策。

#### Scenario: 计数持久化跨关软件
- **WHEN** 某成员仓合并 heal 重试若干次后应用关闭,重开恢复该运行
- **THEN** heal 计数延续(不因重启清零),达上限即回落人工决策

#### Scenario: 收敛后计数清零
- **WHEN** 某失败经 heal 收敛
- **THEN** 该 `(节点, 成员仓)` 的 heal 计数清零

### Requirement: heal agent 复用执行器且提问走既有 agent 决策

临时 heal agent SHALL 经 agent 执行器(无头 adapter / 握手 / 续接阶梯 / 越界检测 / 每节点提交)拉起,读写、限定在卡工作区。heal agent 自身在修的过程中若经握手 `need-decision` 提问,MUST 走既有 `sourceKind='agent'` 决策(落该卡详情面板、选项取自 agent 自填、附自由输入、答复经续接注入回该 heal agent),MUST NOT 新造决策通道。heal 的多次重试 MUST 走续接阶梯(优先原生 resume、否则喂回历史重建)。

#### Scenario: heal agent 提问落单卡走既有通道
- **WHEN** heal agent 经握手写 `need-decision`
- **THEN** 引擎抛 `sourceKind='agent'` 决策落该卡详情面板,用户答复经续接注入回该 heal agent

#### Scenario: heal 重试走续接
- **WHEN** 某成员仓 heal 未收敛、未超限,引擎再次推进该 heal
- **THEN** 引擎按续接阶梯续接原 heal agent、注入上次失败详情,而非从头新拉丢弃半程
