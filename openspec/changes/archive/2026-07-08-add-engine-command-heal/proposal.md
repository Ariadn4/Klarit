## Why

引擎脊柱、命令执行器、卡模型+看板 run、多仓卡分支、agent 执行器都已归档:agent 节点真跑、agent 节点自愈已就位。但**引擎 / 命令节点的技术失败还没 agent 自愈**——引擎 `merge-branch` 一冲突,现在只给人工前进式决策「放弃合并,跳过该节点」(有损:这张卡的活没并进主线就往下走了);命令节点测试没过、命令节点客观门没过,也只会直接打扰人。而 agent 真写代码后、跨卡合并会真冲突、测试会真挂,这些**技术失败该由 agent 代修**,人只在 agent 反复搞不定时才被打扰。失败四归宿里的第 3 类「交给 agent 自愈」在引擎脊柱里明确留了口子(`sourceKind`)、B2 的执行器现成可复用,正是点火的时候。

## What Changes

- **技术失败自动自愈**:引擎遇到「可由 agent 修的技术失败」时,不直接抛人工决策,而是**拉起一个临时读写 heal agent**(复用 B2 执行器)在卡工作区改 / 解,引擎提交后**重跑该失败操作幂等验证**;限次 → 超限 → **回落到现有人工前进式决策**(兜底文案不变)。首发三处:
  - **合并冲突**(引擎 `merge-branch`):**不在主线上解,在卡自己分支上解**——把主线并进卡分支(卡工作区里解),解完卡分支快进合回主线、不再冲突;多仓**逐仓** heal,哪个成员仓冲突就为哪个仓拉一个,各仓独立。
  - **命令主命令非零退出**(测试 / 构建没过):heal agent 改代码 → 引擎提交 → 重跑该命令验证。
  - **命令节点客观门报错**:同上,验证换成重跑那道门。
- **`merge-branch` 保留冲突态模式**:git 写侧合并原语加一个「有 heal 可用时冲突不立即 abort、留给 agent」的模式;默认契约(冲突即干净 abort)不变;超限才由引擎补 abort 回干净态。
- **自由输入 + 转交 AI(除人工评审门外的所有决策)**:除**人工评审门**外,每个决策(引擎/命令失败、客观校验门失败、agent 提问)恒带**一个自由输入框**;提交后——**纯选项**引擎按语义续跑,**含自由输入**转交 AI:**当前有 agent 在跑**(agent 提问/自愈,含正在跑的 heal agent)→ 经续接注入**当前 agent**;**当前无 agent**(引擎/命令失败、客观门失败)→ **新起一个读写 agent**在卡工作区处置(能改就改并提交重验、不能改就解释并把建议作为新选项交回)。**人工评审门本轮不渲染自由输入框**(它要的是"退回哪个节点"的只读回退判定,那套留后续)。
- **观测与记录**:每个 agent 的输出框**展示喂给它的完整 prompt**(含临时 heal / 处置 agent);**所有 agent 运行全量留痕**(完整 prompt + 会话转写 + 握手 + 归宿 + 每仓 SHA + 自愈第几次),持久化可排查。
- **交付验收工作流**:一个真产出东西的小测试项目 + 一条穿过所有排查节点的工作流,拿真 agent 跑,覆盖上述各失败与自愈路径。

**留后续(非本轮)**:**人工评审门驳回**的只读回退 agent(内容驱动回退)、决策**跨卡升级**、用户主动唤起 agent 入口。完整目标设计见 `docs/failure-handling.md`。

## Capabilities

### New Capabilities
- `node-failure-heal`: 引擎 / 命令节点技术失败(合并冲突、命令没过、命令节点客观门没过)的临时 heal agent 自愈编排:何时路由到 heal、合并冲突「在卡分支上解、快进合回」的做法、多仓逐仓 heal、引擎提交 + 幂等重跑验证、限次与超限回落到既有人工决策。

### Modified Capabilities
- `engine-execution`: 失败四归宿的第 3 类「交给 agent 自愈」在**引擎 / 命令节点**落地(不再是「本能力不实现」);`merge-branch` 冲突、命令主命令失败、命令节点客观门失败的归宿由「直接人工」改为「先 heal、超限回落原人工决策」;统一决策结构新增「**除人工评审门外的决策恒带自由输入**」与「提交后处置——纯选项走引擎 / 含自由输入:有当前 agent 注入当前 agent、无当前 agent 新起读写 agent」(人工评审门本轮不渲染自由输入)。
- `git-write-operations`: 合并原语新增「保留冲突态(不立即 abort)」模式,供上层在有 heal 时使用;默认「冲突即干净 abort」契约不变。
- `agent-execution`: 新增**临时读写 agent**(复用无头 adapter / 握手 / 续接 / 越界 / 每节点提交,scope 到卡工作区、生命周期临时)——含**自动 heal agent**(技术失败自愈)与**决策处置 agent**(无当前 agent 决策收到自由输入时新起);续接注入新增「用户对决策的答复(选项 / 自由文本)」;新增**观测**要求(所有 agent 全量留痕 + 输出框展示完整 prompt)。

## Impact

- **代码**:`src/main/git-write.ts`(mergeBranch 保留冲突态模式)、`src/main/engine/ensure.ts`(ensureMerged 接 heal 编排)、`src/main/engine/engine.ts`(引擎 / 命令失败在抛人工前插入 heal 尝试、逐仓编排、决策自由输入注入当前 agent、heal 计数)、`src/main/engine/decisions.ts`(原人工决策保留作回落 + 所有决策加自由输入)、`src/shared/types.ts`(逐仓 heal 状态 + agent 运行记录字段)、`src/main/agent/*`(执行器原样复用,新增 heal prompt 拼装 + 运行留痕)、渲染层(决策自由输入框、输出框展示 prompt)。
- **测试**:先行,用**假 heal agent**(注入把冲突文件写成解决态 / 把命令改到能过并提交的假 runner + 假握手),同 B2 假 adapter/假握手模式,不依赖真 CLI。
- **文档**:`docs/failure-handling.md` 已作为目标设计单一来源;归档时同步增量 spec。
- **交付物**:验收工作流 + 测试项目(dogfood)。
- **无破坏性**:heal 是纯增量插在「抛人工决策之前」;关掉即恢复今日「直接人工」行为,不破坏 engine/command/agent 既有路径。
