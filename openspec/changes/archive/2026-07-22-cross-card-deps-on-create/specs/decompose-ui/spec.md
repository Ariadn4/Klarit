## MODIFIED Requirements

### Requirement: 审阅候选任务窗

「审阅候选任务」窗 SHALL 列出每张候选卡,每张展示:**分类徽章**(`epic`/`feature`/`bug`,徽章文案如 EPIC/FEAT/BUG)、**标题**、**描述(markdown 渲染、非源码)**。点击某张卡 MUST 进入**任务详情**展示该卡细节;详情中**允许用户修改标题与描述**,`typeId`/预取名只读。

**跨卡依赖门的呈现与编辑**:因 `blocked_by` 是 `todo-auto-scheduler` 的**调度硬门**(连错一条边会让卡静默不排),任务详情 SHALL **显式呈现**该候选卡的跨卡依赖边(`blocked_by`/`blocks`),每条标出**被指向卡的当前状态**(如「在跑」/「未开始」/「已完成」),而非只渲染一行 `kind→target` 原文。用户 MAY 在详情里**删除**一条依赖门,并 MAY 新增一条 `blocked_by` 指向全盘中的某张现有卡;所加/所留的边 MUST 过 `requirement-card-model` 的共享边谓词——一条 `blocks` 指向在跑卡 MUST 被拒并给可读原因。层级关系(`parent`/`child`)与预取名保持只读。

**详情视图的返回与页脚**:详情视图的返回入口 MUST 位于**窗口标题栏**,以**统一的 chevron 返回图标**(不使用 `←` 等箭头字符——全 app 返回一律用 chevron,对齐品牌规范「详情返回」)呈现,点击返回候选列表。详情视图 MUST **不渲染**「取消 / 创建任务」页脚——「创建任务」只在**候选列表视图**可点,用户须先返回列表才能创建(避免在单卡编辑态误触发整批落库)。

**列表视图的页脚**:候选列表视图窗底含「取消 / 创建任务」按钮:点击「取消」MUST 关闭窗、丢弃候选;点击「创建任务」MUST 把(含用户编辑后的)候选卡经**统一创建接缝**落库到当前项目(见 `requirement-card-store`)。该窗 MUST **不加蒙层**,样式 MUST 遵循品牌规范与设计令牌、深浅双主题、仅用语义令牌。

#### Scenario: 列出候选卡
- **WHEN** 审阅候选任务窗打开(列表视图)
- **THEN** 每张候选卡展示分类徽章、标题与渲染后的 markdown 描述,窗底含「取消 / 创建任务」,窗体不带蒙层

#### Scenario: 点击卡进详情、标题栏 chevron 返回
- **WHEN** 用户点击某张候选卡进入任务详情
- **THEN** 展示该卡细节,窗口标题栏左侧出现 chevron 返回图标(非 `←`);点击它返回候选列表

#### Scenario: 详情呈现跨卡依赖门与目标状态
- **WHEN** 一张候选卡带 `blocked_by`/`blocks` 指向现有卡,用户进入其任务详情
- **THEN** 详情显式列出这些依赖门,每条标出被指向卡的当前状态(如「在跑」),而非只渲染一行 `kind→target` 原文

#### Scenario: 可删除一条跨卡依赖门
- **WHEN** 用户在任务详情里删除某条 `blocked_by` 门
- **THEN** 该候选卡的对应关系边被移除,创建时不再携带该门

#### Scenario: 详情里加 blocks 指向在跑卡被拒
- **WHEN** 用户在任务详情里试图给候选卡加一条 `blocks` 指向一张在跑卡
- **THEN** 经共享边谓词判非法、给出可读原因,该边不被加入

#### Scenario: 详情视图不渲染创建/取消页脚
- **WHEN** 用户处于某张候选卡的任务详情视图
- **THEN** 窗底 MUST NOT 出现「取消」「创建任务」按钮;须返回候选列表视图后「创建任务」方可点击

#### Scenario: 仅可改标题、描述与跨卡门
- **WHEN** 用户在任务详情里编辑
- **THEN** 标题、描述与跨卡依赖门(`blocked_by`/`blocks`)可改,`typeId`/预取名/层级关系为只读

#### Scenario: 描述以 markdown 渲染
- **WHEN** 候选卡描述含 markdown 标记
- **THEN** 窗内以渲染后的样式呈现,而非展示 markdown 源码

#### Scenario: 列表视图创建任务落库
- **WHEN** 用户在候选列表视图点击「创建任务」
- **THEN** 系统把含编辑的候选卡经统一创建接缝落库到当前项目,再刷新看板、收起流程

#### Scenario: 取消丢弃候选
- **WHEN** 用户在候选列表视图点击「取消」
- **THEN** 关闭窗、丢弃全部候选,不落库
