## ADDED Requirements

### Requirement: 需求卡详情面板

系统 SHALL 在点击看板上一张需求卡时打开一个**需求卡详情面板**,展示该卡的标题、描述(markdown 渲染)、类型徽章、生命周期状态、预取名(作卡标识,非分支——分支仅在真正建出后另行展示,见下),以及——当卡有关联运行(`activeRunId`)时——其运行控制、决策呈现与命令输出入口。面板 MUST 遵循 `docs/brand` 与设计令牌(仅语义令牌、深浅双主题)。

#### Scenario: 点卡打开详情
- **WHEN** 用户点击看板上一张需求卡
- **THEN** 打开该卡详情面板,展示其标题、描述、类型、状态与预取名标识

#### Scenario: 无运行卡的详情
- **WHEN** 打开一张尚未运行(无 `activeRunId`)的卡详情
- **THEN** 展示卡基本信息与「运行」入口,不展示运行控制/决策/输出区

### Requirement: 详情面板的运行控制

需求卡详情面板 SHALL 提供该卡的**运行控制**:未运行时提供「运行」(从卡派生运行请求并触发引擎,见 `requirement-card-store`);运行中提供「暂停」/「恢复」。运行控制 MUST 经既有引擎 IPC(`start`/`pause`/`resume`)操作,渲染层不持有运行生命周期。

当当前节点为 **`command` 执行者且正在执行**(长驻命令如 `npm start` 不会自行退出)时,详情面板 SHALL 额外提供**手动推进控件**(经既有 `advanceCommand`):非末节点给「进入下一节点(转后台)」与「中止并进入下一节点」;**末节点给「中止并完成流程」**——使运行中止该命令并走到终局(已完成),否则运行会永远卡在该命令节点、任务无法完成。手动推进 MUST NOT 被当作命令失败、不抛失败决策。

#### Scenario: 从详情触发运行
- **WHEN** 用户在一张可运行卡的详情面板点「运行」
- **THEN** 系统从该卡派生运行请求并经引擎 `start` 触发,卡获得 `activeRunId`、进入进行中

#### Scenario: 暂停与恢复
- **WHEN** 用户对一张进行中卡的运行点「暂停」再点「恢复」
- **THEN** 经引擎 `pause`/`resume`,运行在阶段边界暂停后又从断点续跑

#### Scenario: 末节点长驻命令可中止并完成流程
- **WHEN** 一张卡的运行停在**末节点**的 `command` 执行(长驻命令不退出)
- **THEN** 详情面板提供「中止并完成流程」按钮,点击后引擎中止该命令并使运行走到终局(卡进入已完成),不抛失败决策

#### Scenario: 非末节点命令可转后台或中止推进
- **WHEN** 一张卡的运行停在**非末节点**的 `command` 执行
- **THEN** 详情面板提供「进入下一节点(转后台)」与「中止并进入下一节点」,点击后运行推进到下一节点(转后台者保留后台命令)

### Requirement: 单卡决策在详情面板内呈现

当一张卡的关联运行处于 `waiting-decision` 时,系统 SHALL 在**该卡详情面板内**呈现其决策(对齐 `docs/project-goals.md`「单卡决策直接展示在需求卡详情面板内,跨卡决策单独弹窗」)。决策渲染 SHALL 复用统一决策结构的全部要素:`titleKey`(+ `titleParams`)翻译后的背景说明、`options`(各按 `labelKey` 翻译、`recommended` 高亮、`detailKey` 作提示)、可选 `input`(填空 + 提交)、`actions`(人工门动作按钮)、`reason`(用户可读失败原因)、`gateHistory`(重试历史)。`raw`(原始底层输出)MUST NOT 在正式 UI 渲染(仅 dev/test)。提交决策经引擎 `decide(runId, { optionId? | optionIds? | text? })`。文案随当前语言实时翻译。跨卡决策弹窗不在本能力范围。

#### Scenario: 等待决策时在详情内显示决策
- **WHEN** 一张卡的运行进入 `waiting-decision`
- **THEN** 该卡详情面板内显示其决策(背景说明 + 前进式选项),不弹独立窗口

#### Scenario: 经卡上红点跳转定位到决策
- **WHEN** 用户点击看板卡上的静止红点(等待决策)入口
- **THEN** 打开该卡详情面板并定位/滚动到决策区,使其可见可操作

#### Scenario: 选项/填空/动作按钮可提交
- **WHEN** 用户在详情内对决策选定某选项、或填入 input、或点某动作按钮
- **THEN** 经引擎 `decide`(或动作入口)提交,运行据回应续跑、决策清除

#### Scenario: 原始输出不在正式 UI 渲染
- **WHEN** 一个决策携带 `raw` 字段
- **THEN** 正式 UI 不渲染 `raw`(仅 dev/test 可见),用户只看 `titleKey`/`reason` 等可读文案

#### Scenario: 决策文案随语言实时翻译
- **WHEN** 用户在决策展示期间切换界面语言
- **THEN** 决策的背景与选项文案据新语言实时翻译

### Requirement: 命令输出按前台/各后台任务分流且可回看

需求卡详情面板 SHALL 为该卡运行的命令输出提供**按条分流、可回看**的入口,而非把多条命令输出杂糅一处:

- **前台当前命令**:以运行圆点(呼吸蓝点)及其后方节点文案作为入口,点击后展示**当前运行命令**的输出。
- **各后台命令**:展示该运行的后台命令条目(每个 `bgId` 一行,带其节点/标签),每行可点入查看**该后台命令各自**的输出(可同时存在多个后台命令)。

**后台命令终止后 MUST NOT 直接消失**:一个后台命令被用户中止 / 自行退出 / **超时被杀**时,其条目 SHALL **保留在详情面板并标注终态**(如「已中止」「已结束」「已超时中止」——尤其"计时中止"要显式可见,以免用户误以为是 bug),直到**用户点击「清除」**才移除该条目;运行中的后台命令则提供「中止」。终态条目的输出仍 SHALL 可回看。

输出 MUST **可回看**(不只在流过时即时显示):依赖引擎对命令输出按命令/后台任务分桶缓冲(见 `engine-execution`);**命令转后台后其后续输出归入该后台命令自己的桶**(不再混入前台节点桶)。关闭重开后,仍能回看运行期内已缓冲的输出。

#### Scenario: 经蓝点入口看前台命令输出
- **WHEN** 一张卡运行中其前台节点正在跑命令(呼吸蓝点),用户点击该点/文案入口
- **THEN** 展示当前命令的输出(可回看已产出的部分,非仅实时片段)

#### Scenario: 多个后台命令各自可点入查看
- **WHEN** 某运行有两个以上后台命令
- **THEN** 详情面板分别列出每个后台命令,各有独立入口查看其各自输出(转后台后的输出进各自的桶,不再是「暂无输出」)

#### Scenario: 后台命令超时中止后保留并标状态
- **WHEN** 一个带超时的后台命令到点被杀
- **THEN** 其条目保留在详情面板并标注「已超时中止」(不直接消失),并提供「清除」按钮;用户点「清除」后方移除该条目

#### Scenario: 关重开后输出仍可回看
- **WHEN** 一个产生过命令输出的运行随应用关闭后重开并恢复
- **THEN** 用户仍可在详情面板回看运行期内已缓冲的命令输出

### Requirement: 卡上分支名仅在分支落地后展示并联动 git 视图

需求卡的**预取名**只是"打算用的分支名",不代表已有分支。故卡面 MUST NOT 在分支尚未创建时展示分支名。仅当该卡在本地**真正建出对应 worktree/分支**(由其运行的 `worktreePath` 派生、探测确认存在)时,才 SHALL 展示分支名,且展示的 MUST 是**引擎实际使用的分支名**(取自运行断点 `request.branch`,占用等情形下可能与预取名不同),而非预取名。已展示的分支名 SHALL **可点击**:点击后侧边栏切到 git 视图并**程序化聚焦**到(该卡首仓, 该实际分支)对应的 worktree(见 `sidebar-git-view`)。

#### Scenario: 分支未落地时不展示分支名
- **WHEN** 一张卡尚未运行、或运行尚未建出 worktree/分支
- **THEN** 卡面不展示任何分支名(预取名不作分支展示)

#### Scenario: 分支落地后展示实际分支名并可点跳转
- **WHEN** 一张卡的运行已建出对应 worktree,用户点击其分支名
- **THEN** 卡面展示引擎实际使用的分支名(取自运行断点,非预取名),点击后侧边栏切到 git 视图并聚焦到该卡首仓与该分支对应的 worktree 目录

### Requirement: 退役 dogfood 试跑卡

本能力落地后,临时的 dogfood 试跑卡(`DogfoodRunCard` / `DogfoodPanel` / `dogfood-cards`)SHALL 被移除——其运行控制与 i18n 决策 UI 已迁入需求卡详情面板的可复用决策组件。移除后系统 MUST 不再依赖 dogfood 路径触发或观察运行。

#### Scenario: dogfood 卡不再存在
- **WHEN** 本能力实现完成
- **THEN** 代码库不再含 dogfood 试跑卡及其面板,运行的触发/决策/输出均经需求卡详情面板
