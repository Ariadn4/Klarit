## Why

现在导入一个含多个 git 子仓的目录会弹「发现 N 个子仓，组成多仓项目？」确认横条，多此一举；而且组建后侧边栏把项目拆成两个 git 仓分组来展示，违背用户「打开哪个文件夹、它就是项目目录」的直觉——用户要的是一个像资源管理器一样、直接列出项目目录下所有文件夹与文件的文件树。同时管理面板的「打开本地项目」因为旧的确认流程而无法直接导入多仓项目。

## What Changes

- **取消多仓确认横条**：导入一个自身非 git、其下含多个 git 子仓的目录时，系统直接组建多仓项目，不再弹确认条、不再需要用户点「组成多仓项目」。
- **项目以「目录」为根**：文件树视图统一以**项目目录**为根（用户打开的那个文件夹），像资源管理器一样列出其下所有文件夹与文件——单仓、多仓、gitless 目录都一样，**不再**按成员 git 仓拆成分组，子仓在树里只是普通文件夹。项目目录**不另存绝对路径**，而是从成员仓的最近已知路径派生（单仓=该仓路径；多仓=各成员仓的公共父目录），从而在云同步/换机器/换盘符后随成员 `.klarit/project-id` 自动归位。
- **管理面板支持多仓导入**：管理项目窗口的「打开本地项目」选中含多个子仓的目录时，直接组建并打开多仓项目（不再提示「请从主窗口侧边栏导入」）。
- **缺失处理改到项目目录层级**：项目目录在磁盘上不存在时，文件树区给出「目录找不到」提示（可移除项目；单仓可重新定位），不再在文件树里逐个成员仓显示缺失/解绑入口。
- **BREAKING**（行为）：多仓项目侧边栏文件树视图不再按成员仓分组；导入多仓不再有确认步骤。git 视图仍按成员仓选择分支（不变）。

### Modified Capabilities
- `project-registry`: 导入含子仓的目录改为**直接组建**多仓项目（去掉「提议/确认」），并凭**成员身份**复用既有项目（换机器/同步后复原分组）；**项目目录由成员仓路径派生**（不另存绝对路径）。
- `multi-repo-project`: 自动组建（无需确认）；侧边栏文件树由「按成员仓分组」改为「以项目目录为根的资源管理器式文件树」；缺失处理上移到项目目录层级。
- `app-shell-sidebar`: 「当前项目目录文件树」统一为以项目目录为根列出全部子项（单仓/多仓一致），去掉成员仓分组层。
- `manage-projects-window`: 「打开本地项目」支持选中含多子仓的目录时直接组建并打开多仓项目。

## Impact

- 数据模型：**不新增持久字段、无数据迁移**；项目目录由成员仓路径派生（新增共享 helper `projectRootPath(project)`，main 与 renderer 共用）。
- 主进程：`importProject` 对含子仓目录直接组建、凭成员身份去重（去掉 `nested-candidates` 返回与 `confirmNestedProject` IPC）；`ImportOutcome` 简化为 `{ project, reused }`；文件监听改为监听派生出的项目目录。
- 预加载/渲染：移除 `confirmNestedProject` 与 App 的确认横条状态；`Sidebar` 文件树视图改为 `FileTree rootPath={project.rootPath}`，移除 `RepoGroup` 在文件树视图的使用；管理面板去掉多仓提示分支。
- git 视图（`GitView`）、成员身份与 git 检测/补绑逻辑不变。
