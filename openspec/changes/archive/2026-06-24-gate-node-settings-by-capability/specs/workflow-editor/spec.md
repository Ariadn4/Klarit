## ADDED Requirements

### Requirement: 节点设置块按执行者能力呈现

节点详情对「**可写范围**」「**产出**」「**检查（门）**」三块的呈现 SHALL 由**当前执行者的能力**驱动，而非无条件常显。某块当且仅当当前执行者声明需要该能力时呈现；不呈现的块不渲染其任何控件、其对应字段保持空（不写入定义）。能力按执行者类型解析：

- `agent`：三块**全部呈现**（agent 会写代码/交付文档、需可写范围与门，行为不变）。
- `engine`：按**所选具体操作**的能力声明（见 `workflow-definition`「引擎内置操作的能力声明」）**逐块**呈现——某操作的某项能力为否则隐藏对应块；**未选操作**时三块全隐。当前 4 个引擎操作三项能力皆否，故其下三块均不呈现。

未来若新增任一项能力为真的引擎操作，编辑界面 MUST 据其能力声明自动呈现对应块，无需改动界面的显隐逻辑。

#### Scenario: agent 节点三块全显
- **WHEN** 用户打开一个 `agent` 执行者节点的详情
- **THEN** 可写范围、产出、检查三块均呈现并可编辑

#### Scenario: 现有引擎操作隐藏三块
- **WHEN** 用户打开一个 `engine` 执行者节点并选中 `create-branch`（或其它现有引擎操作）
- **THEN** 可写范围、产出、检查三块均不呈现

#### Scenario: 未选引擎操作时隐藏三块
- **WHEN** 用户把节点执行者切到 `engine` 但尚未选择具体操作
- **THEN** 可写范围、产出、检查三块均不呈现

#### Scenario: 切换引擎操作按能力更新显隐
- **WHEN** 用户在 `engine` 节点把所选操作改为一个声明了某项能力为真的操作
- **THEN** 编辑界面据该操作的能力声明自动呈现对应的块（能力为否的块仍隐藏）

## MODIFIED Requirements

### Requirement: 产出与门的编辑

工作流编辑界面 SHALL 允许为**声明了对应能力的节点**（见「节点设置块按执行者能力呈现」）编辑其**产出**与**门**；对未声明该能力的执行者（如现有的所有 `engine` 操作）不呈现这两块：

- 产出：可新增/删除条目，每条可编辑 **file 目的地路径**（相对路径、须 `.md`，文件名即标识、扩展名即格式）、**模板**、必选/可选。模板只「**不声明 / 从规则库引用**」二选——内容统一住规则库、工作流不嵌入。引用态提供：选已有 `output-template` 条目；**「新建」**（填「存入哪个规则包」+ 名称 + 内容，保存即把条目写进规则库并引用它）；**「编辑」**（当前引用的条目，改其内容写回规则库）。v1 不呈现卡片数据目的地（待需求卡数据模型落地再开）。
- 门：可新增/删除有序门把，每道选类型（自动校验/人工评审），**不带「说明」字段**；并按类型呈现差异字段：
  - **自动校验**：校验提供「**裸命令 / 从规则库引用**」二选——裸命令＝填一条命令（必填）、引用＝选一个 `objective-check` 条目；及可选的**校验目标**——从本节点已声明产出中按路径择取零或多个。
  - **人工评审**：一个**动作按钮**列表，每个按钮含**文案**与**命令**；切到人工评审时**直接预置一行**（文案 + 命令）输入框，可继续增/删，完全空白的行在保存时自动剔除（零按钮亦合法）。

从规则库引用时，编辑界面 SHALL 以下拉/选择器从规则库列出可选条目（按类型过滤——模板处只列 `output-template`、自动校验处只列 `objective-check`），底层以条目 id 记录引用。引用一个本机暂缺的条目不阻塞保存（见 `workflow-definition`）。

#### Scenario: 编辑产出（从规则库引用模板）
- **WHEN** 用户为某节点新增一个产出并填写 file 路径，模板选「从规则库引用」并选一个 `output-template` 条目
- **THEN** 该产出随节点一起保存，模板形态（none/ref）被保留；选 ref 时记录所选条目 `{packId, itemId}`

#### Scenario: 模板「新建」把内容写进规则库再引用
- **WHEN** 用户在产出模板的引用态点「新建」，选存入哪个规则包、填名称与内容、保存
- **THEN** 该内容作为一个 `output-template` 条目写进所选规则包（经 `rule-pack-model` 校验），编辑界面随即引用它（工作流不内嵌该内容）

#### Scenario: 编辑自动校验门把（裸命令或引用）
- **WHEN** 用户新增一道自动校验门把，校验选「裸命令」填写命令、或选「从规则库引用」选一个 `objective-check` 条目，并（可选）勾选若干校验目标
- **THEN** 该门把连同校验形态（inline/ref）与目标随节点一起保存

#### Scenario: 编辑人工评审门把的动作按钮
- **WHEN** 用户把门把切到人工评审
- **THEN** 编辑界面**直接呈现一行动作按钮输入（文案 + 命令）**，填写后随门把保存、抛出决策时据此渲染

#### Scenario: 切换门把类型呈现对应字段
- **WHEN** 用户把某门把类型在「自动校验」与「人工评审」间切换
- **THEN** 编辑界面相应呈现「校验（裸命令/引用）+ 目标」或「动作按钮列表（预置一行文案+命令）」字段，且不呈现任何「说明」输入

#### Scenario: 规则库引用按类型过滤可选条目
- **WHEN** 用户在产出模板处或自动校验处选择「从规则库引用」
- **THEN** 选择器仅列出对应类型的条目（模板处只列 `output-template`、校验处只列 `objective-check`）

#### Scenario: 无产出/门能力的执行者不呈现两块
- **WHEN** 用户打开一个执行者为现有 `engine` 操作的节点详情
- **THEN** 编辑界面不呈现产出与门两块（这些操作不交付文档、不跑客观门）
