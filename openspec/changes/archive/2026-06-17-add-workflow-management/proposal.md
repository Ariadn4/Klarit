## Why

Klarit 的核心是「根据配置的工作流自动处理需求」（见 `docs/project-goals.md`：四层产品结构里工作流是一等层、引擎几乎所有能力都从「当前项目用哪个工作流」展开）。但现在工作流还不是一个能被创建、保存、切换的东西——连承载它的数据实体和管理入口都没有。

这次先把**工作流立成一等持久对象**并给一个管理入口：用户能新建/克隆/删除工作流、用表单编辑它的字段、给当前项目切换激活哪个工作流。这是后续「执行引擎」change 的地基——先有可被引用、可被编辑、可被分享的工作流定义，引擎才有东西可跑。

本次**明确不做执行引擎**（不拉起 agent、不跑节点、不过门），也**不做可视化 DAG 画布**——v1 只支持线性工作流，节点用可拖拽排序的列表表达。

## What Changes

- 新增**工作流定义**数据模型：阶段（看板列）+ 有序节点列表，节点含执行者（agent/engine/command/subworkflow 四选一）、驱动指令、产出声明、可写范围、门，对齐 `project-goals.md`「工作流与节点」一节。v1 为线性（单线），节点顺序即执行顺序。
- 工作流**以「包目录」持久化**在 Klarit 管理数据目录（`userData/workflows/<id>/`，内含 `workflow.yaml` 与被引用的 skill 文件），不入 git；包是自包含、可移植、可整体云同步的单位，YAML 即对外开放的导入/导出格式（满足 project-goals「导入格式 v1 必须开放」）。
- 新增**工作流库**能力：列出/新建/克隆/删除/导入/导出工作流定义；首启**种入一个内置默认工作流**作为起点与样例。
- 新增**工作流编辑器**（表单式，非画布）：每个字段一个输入控件；节点为有序列表，支持**拖拽改顺序**（@dnd-kit）；保存即写回该工作流的 YAML。
- 设置面板新增「**项目设置**」区（与 app 级的「语言」区分开），承载：当前项目**激活工作流的选择器（切换）** + 工作流库管理（新建/克隆/删除/编辑入口）。
- 每个**项目记录其激活的工作流 id**（项目级归属，存项目管理数据，不入 git）；切换工作流 = 改当前项目的激活指针。删除被某项目激活的工作流前需处理该引用。

## Capabilities

### New Capabilities
- `workflow-definition`: 工作流的数据模型与「包目录」持久化——阶段/节点/执行者/产出/可写范围/门的结构、agent 驱动指令的 inline/file 形态、校验规则、`userData/workflows/<id>/`（含 `workflow.yaml` 与 skill 文件）读写、导入/导出、首启默认工作流种子。
- `workflow-library`: 工作流库的管理操作——列出、新建（含默认模板）、克隆、删除、导入/导出，及其经 IPC 暴露给渲染层的契约。
- `workflow-editor`: 设置面板内的表单式工作流编辑界面——字段级输入控件、节点有序列表与拖拽排序、保存写回。

### Modified Capabilities
- `settings-panel`: 新增「项目设置」区，内含当前项目的工作流激活选择器与工作流库管理入口；与既有 app 级「语言」区在视觉与语义上分区。
- `project-registry`: 项目记录其**激活工作流 id**；提供读取/设置激活工作流的行为；删除工作流时正确处理被引用的项目指针。

## Impact

- **主进程**：新增工作流库服务（CRUD + YAML 序列化 + 校验 + 默认种子），读写 `userData/workflows/`；扩展项目注册表持久化以记录每项目激活工作流 id；通过 IPC 暴露库操作与激活读写。复用 `store.ts` 的读写约定。
- **依赖**：新增 YAML 解析/序列化库（按 CLAUDE.md「依赖默认上前沿」先 `npm view` 取 latest）。
- **共享层**：`src/shared/types.ts` 新增工作流定义/节点/执行者等类型，并扩展 `KlaritApi` IPC 契约与 `Project` 模型（激活工作流 id）。
- **渲染层**：`Settings.tsx` 新增「项目设置」区与工作流库/编辑器子界面；新增工作流相关 zustand 状态；UI 遵循 `docs/brand/klarit-brand-system.html` 与 `index.css` 的 `@theme` 令牌。
- **不影响**：既有语言设置、侧边栏、项目导入与多仓行为；不引入任何 agent 执行 / git 写操作。
