## ADDED Requirements

### Requirement: 新建需求入口（临时落点）

渲染层 SHALL 提供一个「新建需求」入口，点击即打开「描述想法」窗。本 change 的入口落点为**临时最小落点**（先接通分解链路），正式位置随需求看板的后续 change 再定。该入口 MUST 在当前窗口未绑定任何项目时给出明确空态（无处归属需求，见 `global-agent`），不报错。

#### Scenario: 点击新建需求打开描述想法窗
- **WHEN** 用户在已绑定项目的窗口点击「新建需求」
- **THEN** 打开「描述想法」窗

#### Scenario: 未绑定项目时的空态
- **WHEN** 当前窗口未绑定任何项目，用户点击「新建需求」
- **THEN** 给出明确空态提示，不打开描述想法窗、不报错

### Requirement: 描述想法窗

「描述想法」窗 SHALL 含：一个**「附件」按钮**、一个**多行描述输入**、底部「取消 / 提交」按钮，及一段提示文案「请描述想法（可一次写下多条）；可 Ctrl+V 粘贴截图、拖入文件插入其路径」。该窗 MUST **不加蒙层**（无 scrim 遮罩），且可最小化/关闭。**附件统一以路径形式即时插入正文**（而非单列附件区）：

- 点击「附件」按钮 MUST 打开**系统文件选择器**（可多选），所选文件的路径插入正文。
- **Ctrl+V 粘贴截图** MUST 把该图落盘到受管目录后，将其路径插入正文。
- **拖入文件** MUST 取其本地路径插入正文。

点击「提交」MUST 携带描述发起分解（见 `requirement-decomposition`）；点击「取消」MUST 关闭窗、不发起分解。窗体样式 MUST 遵循品牌规范（`docs/brand`）与 `index.css` 的 `@theme` 设计令牌、支持深浅双主题、仅用语义令牌。

#### Scenario: 描述想法窗的构成
- **WHEN** 描述想法窗打开
- **THEN** 展示「附件」按钮、多行描述输入、取消/提交按钮与提示文案，且不带蒙层

#### Scenario: 附件按钮打开系统选择器并把路径插入正文
- **WHEN** 用户点击「附件」按钮并在系统文件选择器中选中一个或多个文件
- **THEN** 所选文件的路径被插入到正文描述中

#### Scenario: 粘贴截图落盘后路径插入正文
- **WHEN** 用户在描述想法窗内 Ctrl+V 粘贴一张截图
- **THEN** 该截图落盘到受管目录，其路径被插入到正文描述中

#### Scenario: 拖入文件插入路径
- **WHEN** 用户把一个文件拖入描述想法窗
- **THEN** 该文件的本地路径被插入到正文描述中

#### Scenario: 提交发起分解
- **WHEN** 用户点击「提交」
- **THEN** 系统携带描述发起分解，进入处理态

#### Scenario: 取消不发起分解
- **WHEN** 用户点击「取消」
- **THEN** 描述想法窗关闭，不发起分解

### Requirement: 处理态隐藏与底栏「建卡中」

提交后 AI 处理期间，描述想法窗 SHALL **隐藏**（不停留遮挡界面），并在**底栏**显示一个「建卡中」指示（带处理中图标），表示正在建卡。处理期间用户**再次点击「新建需求」**（或点底栏「建卡中」）MUST 重新弹出处理窗并提示「正在处理需求」（而非另起一次新的分解或新的描述窗）。处理窗 MUST **只含一个「收起」按钮**（收回底栏），**不含关闭(×)**——收起不中断分解、不清空，底栏「建卡中」指示 MUST 一直存在直至处理完成。处理完成后 MUST 自动弹出「审阅候选任务」窗（见下）、底栏指示消除。底栏指示样式 MUST 遵循品牌规范与设计令牌、深浅双主题。

#### Scenario: 处理时隐藏并收底栏
- **WHEN** 用户提交描述、AI 开始处理
- **THEN** 描述想法窗隐藏，底栏出现「建卡中」处理态指示

#### Scenario: 处理中再点新建需求显示正在处理
- **WHEN** 处理进行中用户再次点击「新建需求」或底栏「建卡中」
- **THEN** 重新弹出处理窗并提示「正在处理需求」，不发起第二次分解、不弹新的描述窗

#### Scenario: 处理窗只「收起」不关闭、建卡中持续
- **WHEN** 用户在处理窗点「收起」
- **THEN** 处理窗收回底栏、分解不中断，底栏「建卡中」指示仍在，直至处理完成

#### Scenario: 处理完成弹出审阅窗
- **WHEN** 分解处理完成、产出候选卡
- **THEN** 自动弹出「审阅候选任务」窗，底栏「建卡中」指示消除

### Requirement: 审阅候选任务窗

「审阅候选任务」窗 SHALL 列出每张候选卡，每张展示：**分类徽章**（`epic`/`feature`/`bug`，徽章文案如 EPIC/FEAT/BUG）、**标题**、**描述（markdown 渲染、非源码）**。点击某张卡 MUST 弹出**任务详情**展示该卡细节。详情中**仅允许用户修改标题与描述**，其它字段（分类、预取名、关系）只读。窗底含「取消 / 创建任务」按钮：点击「取消」MUST 关闭窗、丢弃候选；点击「创建任务」MUST 把（含用户编辑后的）候选卡交给创建接缝——**该接缝之后的落库工作归下一个 change**（见 `global-agent`、`requirement-card-model`）。该窗 MUST **不加蒙层**，样式 MUST 遵循品牌规范与设计令牌、深浅双主题、仅用语义令牌。

#### Scenario: 列出候选卡
- **WHEN** 审阅候选任务窗打开
- **THEN** 每张候选卡展示分类徽章、标题与渲染后的 markdown 描述，且窗体不带蒙层

#### Scenario: 点击卡看详情
- **WHEN** 用户点击某张候选卡
- **THEN** 弹出任务详情展示该卡细节

#### Scenario: 仅可改标题与描述
- **WHEN** 用户在任务详情里编辑
- **THEN** 仅标题与描述可改，分类/预取名/关系为只读

#### Scenario: 描述以 markdown 渲染
- **WHEN** 候选卡描述含 markdown 标记
- **THEN** 窗内以渲染后的样式呈现，而非展示 markdown 源码

#### Scenario: 创建任务交给下一个 change
- **WHEN** 用户点击「创建任务」
- **THEN** 系统把含编辑的候选卡交给创建接缝，本 change 止于此（落库/建分支等由下一个 change 实现）

#### Scenario: 取消丢弃候选
- **WHEN** 用户点击「取消」
- **THEN** 审阅窗关闭，候选卡被丢弃、不交给创建接缝
