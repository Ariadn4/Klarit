## ADDED Requirements

### Requirement: 全局 agent 作为「新建需求」产出者的接缝

系统 SHALL 建立**全局 agent**作为「新建需求」产出者的最小接缝，对齐 `docs/project-goals.md`「三层 Agent 结构」中全局 agent「用户新建需求卡」的职责。该接缝 SHALL 接收一段自由描述与当前项目上下文、调用 `requirement-decomposition` 解析生效 prompt 并产出**候选需求卡**回传供人审（见 `decompose-ui`）。「新建需求」入口与全局 agent / 外部 AI 的调用 MUST 走**同一条接缝**，不各自实现一套产出逻辑。

产出候选卡时 SHALL **真实调用用户配置的默认 agent**（无头 CLI 调用、复用用户订阅、不自建模型通道）跑生效分解 skill 并解析其回复为候选卡；未配置 agent 或调用失败 MUST 优雅降级为空候选（审阅显空态），不报错、不崩溃。本 change 只打通到**产出候选卡**为止；点击「创建任务」之后的落库、建分支、启动工作流，以及全局 agent 对话 UI 与写代码的 PTY 交互式后台执行 agent 运行时，**归下一个 change**。

#### Scenario: 产出候选卡时真实调用配置的 agent
- **WHEN** 当前已配置默认 agent，用户提交一段描述
- **THEN** 接缝无头调用该 agent 跑分解 skill，并把其回复解析为结构化候选卡回传

#### Scenario: 未配置 agent 或调用失败时优雅空态
- **WHEN** 未配置默认 agent，或 agent 调用失败/超时
- **THEN** 接缝返回空候选（审阅显空态），不报错、不崩溃

#### Scenario: 「新建需求」经全局 agent 接缝产出候选
- **WHEN** 用户提交一段自由描述
- **THEN** 系统经全局 agent 接缝解析 prompt、产出候选卡并回传供人审

#### Scenario: 入口与调用共用同一接缝
- **WHEN** 「新建需求」入口与外部调用分别发起分解
- **THEN** 两者经同一「解析 prompt → 产出候选卡」接缝完成，行为一致

#### Scenario: 创建落库归下一个 change
- **WHEN** 用户在审阅窗点击「创建任务」
- **THEN** 接缝把候选卡交出，本 change 不执行落库/建分支（由下一个 change 接手）

### Requirement: 全局 agent 只读且挂当前项目

全局 agent 接缝在「新建需求」一事上 SHALL **只产出管理状态用的候选卡**、**不触碰项目代码 / git**（对齐三层结构中全局 agent 的只读定位）。候选卡 MUST 关联**当前窗口绑定的项目**上下文（含其涉及成员仓候选，供取分支名/预取名）。当当前窗口**未绑定任何项目**时，接缝 MUST 给出明确空态（无处归属需求），不报错、不产出悬空候选。

#### Scenario: 候选关联当前项目
- **WHEN** 在已绑定项目的窗口经接缝产出候选
- **THEN** 候选卡携带该项目上下文，且未改动任何项目代码 / git

#### Scenario: 未绑定项目时的空态
- **WHEN** 当前窗口未绑定任何项目，触发「新建需求」
- **THEN** 接缝给出明确空态提示，不产出候选、不报错

### Requirement: 分解 skill 可被外部 AI 直接调用

为使「如果用户直接跟全局 agent / 外部 AI 聊天也能成功创建需求」，系统 SHALL 使分解 skill（生效 prompt 与候选卡输出契约）**可被外部 AI 读取并执行**：外部 AI 按 skill 产出结构化候选卡，经同一接缝进入人审。该路径 MUST 复用同一分解 prompt 解析顺序与同一候选卡校验，不旁路卡模型校验。

#### Scenario: 外部 AI 按 skill 产出候选
- **WHEN** 外部 AI 读取生效分解 skill、产出结构化候选卡并经接缝提交
- **THEN** 候选卡进入与「新建需求」入口一致的人审流程

#### Scenario: 外部路径不旁路校验
- **WHEN** 外部 AI 产出的候选卡含非法字段（如空标题、非法预取名）
- **THEN** 这些候选被同一卡模型校验标记并附原因，供人审界面提示，不被当作合法卡
