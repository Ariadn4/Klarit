## MODIFIED Requirements

### Requirement: 导入项目

用户 SHALL 能通过选择一个本地目录把项目导入 Klarit。一次导入 MUST 建立或扩充一个由**一个或多个成员仓**组成的项目：

- 选中的目录是单个 git 仓（或 gitless 目录）时，行为与扩展前一致——以该目录的文件夹名作为项目默认名，作为成员数为 1 的项目登记。
- 选中的目录自身不是 git、其直接子目录中含多个 git 仓时，进入多仓组建流程（见 `multi-repo-project`）。

系统 MUST 以可读名称命名项目（单仓取仓库目录文件夹名；多仓取容器目录文件夹名作默认名，可编辑）。同一成员仓（按其持久身份判定）重复导入 MUST 不产生重复登记，而是复用既有成员条目并更新其记录路径。

#### Scenario: 选择目录导入新项目
- **WHEN** 用户在导入流程中选择一个尚未导入的单个 git 仓库或 gitless 目录
- **THEN** 系统以该目录的文件夹名作为项目名，作为成员数为 1 的项目加入注册表

#### Scenario: 重复导入同一成员仓不重复登记
- **WHEN** 用户导入一个其持久身份已存在于注册表中的仓（如换了路径的同一仓库）
- **THEN** 系统复用既有成员条目而非新建，并更新其记录的最新路径

#### Scenario: 容器目录含多子仓进入多仓组建
- **WHEN** 用户选择的目录自身不是 git、其下含多个 git 子仓
- **THEN** 系统进入多仓组建流程（按 `multi-repo-project` 提议把子仓组成一个项目）
