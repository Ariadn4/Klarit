## ADDED Requirements

### Requirement: 外部门的打回亦触发内容驱动回退（origin-aware 回落）

内容驱动回退的**发起入口**此前只有「人工评审门驳回自由输入」。系统 SHALL 使**外部门**（`external`，见 `engine-execution`「引擎执行外部门」）的**打回自由输入亦触发同一内容驱动回退**——复用**同一只读回退判定 agent → 回退确认 → 重入目标节点前向修复**（不各造一套）。这使「PR 被平台打回 / 用户想改」时，反馈能退回到之前节点改代码。

回退 MUST **origin-aware**：引擎在发起回退时 SHALL 记住**触发它的那道门**；当判定 agent 无候选、无判定 agent、或用户在回退确认里取消时，引擎 MUST **重抛那道门**——人工评审门发起的重抛评审门（`通过`/`驳回`），外部门发起的重抛该外部门（「开始收尾」），而非固定回评审门。为此 `raiseManualGate` SHALL 一般化为按当前门 `kind` 分派重抛的 `raiseGate`。

此扩展**只针对「门」（人工评审门 / 外部门）**——它们的语义本就是「人/外部确认，不满意打回」。普通引擎失败决策（命令失败、push 认证等，无门）的自由文本路由**不变**（仍走既有处置 agent），MUST NOT 因本扩展改道回退：那类反馈有的就是本节点的活、该就地改，强行都退回易挑错节点或成环。

重入后 `drive()` 前向重流 SHALL 自然重跑下游（如 `push-feature` **re-push 更新平台 PR** → `open-pr` 幂等 noop → 外部门再核查），使「PR 被打回 → 改代码 → 更新 PR → 再等合并」闭环成立。

#### Scenario: 外部门打回触发回退
- **WHEN** 用户在 `verify: 'pr-merged'` 外部门的自由输入里写「HELLO.md 要加中文版」
- **THEN** 引擎拉起只读回退判定 agent 定位回退节点（如 `implement`）→ 回退确认，而**不**新起就地处置 agent

#### Scenario: 回退 origin-aware 重抛外部门
- **WHEN** 判定 agent 无候选、或用户在回退确认里取消，且本次回退**发起自外部门**
- **THEN** 引擎重抛该**外部门**（「开始收尾」）决策，而非评审门决策

#### Scenario: 前向重流更新 PR 再核查
- **WHEN** 用户确认从 `implement` 重入，前向重流经 `push-feature`、`open-pr`、外部门
- **THEN** `push-feature` re-push 更新平台上的 PR、`open-pr` 幂等 noop、外部门重新核查合并

#### Scenario: 普通引擎失败决策不改道回退
- **WHEN** 一个非门的 engine/command 失败决策被写入自由文本
- **THEN** 仍走既有处置 agent（就地能改就改），不因本扩展改走回退

## MODIFIED Requirements

### Requirement: 回退确认决策

引擎 MUST 把判定 agent 的握手决策渲染成一个**回退确认决策**,复用既有决策面板:

- `options` 承载**主选 + 若干备选**回退节点(每项带节点名与理由);自由输入框保留,用户在此写内容可**重唤判定 agent** 再判一轮。
- 抛出确认决策前,引擎 MUST 记录当前**最远进展节点**(`furthestNodeId`),供重入后的续接注入告知「之前推进到哪」。
- 用户确认某目标节点则执行重入;用户取消则**重抛发起本次回退的那道门**——人工评审门发起的重抛评审门(`通过`/`驳回`),外部门发起的重抛该外部门(「开始收尾」),均不丢失该门。

#### Scenario: 确认决策以选项呈现主选与备选
- **WHEN** 判定 agent 给出主选节点 + 备选节点
- **THEN** 引擎抛出的确认决策以 `options` 列出它们(主选标推荐),并保留自由输入框

#### Scenario: 确认前记录最远进展节点
- **WHEN** 引擎抛出回退确认决策
- **THEN** 断点已记录当前最远进展节点 `furthestNodeId`

#### Scenario: 自由输入重唤判定
- **WHEN** 用户对确认决策写下新的自由输入并提交
- **THEN** 引擎再次拉起回退判定 agent,据新输入重判

#### Scenario: 取消回退重抛发起它的门
- **WHEN** 用户取消回退确认(本次回退发起自人工评审门或外部门)
- **THEN** 引擎重抛发起本次回退的那道门(评审门→`通过`/`驳回`;外部门→「开始收尾」),不丢失
