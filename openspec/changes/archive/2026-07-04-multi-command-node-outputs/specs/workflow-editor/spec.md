## ADDED Requirements

### Requirement: command 节点的多命令列表编辑

`command` 执行者节点的设置块 SHALL 把命令呈现为**一条以上命令行的列表**(对应 `workflow-definition` 的 `commands: CommandSpec[]`),而非单一命令输入。每行含:**命令行**(必填)、可选**标签**、可选**前置检查命令**、可选**超时(秒)**。编辑器 SHALL 在打开一个 `command` 节点时**至少预置一行**,允许用户**增行/删行**;完全空白的行(命令行为空)在保存时**自动剔除**;剔除后 MUST **至少保留一条命令行非空**,否则按 `workflow-definition` 校验(`commands` 非空)拒绝保存并提示。

#### Scenario: command 节点呈现多命令列表并可增删
- **WHEN** 用户打开一个 `command` 执行者节点的详情
- **THEN** 呈现命令行列表(至少预置一行),可增行/删行,每行含命令行 + 可选标签/前置检查/超时

#### Scenario: 空白命令行保存时剔除
- **WHEN** 用户在多命令列表里留有若干完全空白的行并保存
- **THEN** 空白行被自动剔除,仅非空命令随节点保存;若剔除后无任何命令则保存失败并提示至少需一条命令

#### Scenario: 多命令往返保持
- **WHEN** 用户为一个 `command` 节点填写两条命令(各含命令行与可选字段)并保存后重开
- **THEN** 两条命令及其字段完整回显在列表中

## MODIFIED Requirements

### Requirement: command 节点的前置检查命令编辑与软提示

`command` 执行者节点的多命令列表中,**每一行命令** SHALL 各提供一个可选**前置检查命令**输入(对应该行 `CommandSpec` 的 `check` 字段),并在其旁呈现一段**软提示**,引导作者为不幂等命令补上前置检查,以避免中断恢复时重复执行。该提示为**纯引导**——编辑器 MUST NOT 强制要求填写前置检查(系统无法可靠判别命令是否幂等),仅在用户填写后按 `workflow-definition` 的结构校验(声明则非空)参与保存校验。

软提示文案 SHALL 以「非幂等命令(跑一次生效后重跑会重复或产生副作用,如数据库迁移、版本号自增、发送通知等)建议加前置检查」为意,**不以部署/发布为例**(该类引导走引擎操作)。提示文案为 i18n、随语言切换。

#### Scenario: 每行命令呈现前置检查输入与提示
- **WHEN** 用户打开一个 `command` 执行者节点的详情
- **THEN** 每行命令呈现「命令」与可选「前置检查命令」输入,且前置检查旁有引导软提示

#### Scenario: 前置检查为可选不阻塞保存
- **WHEN** 用户未填写某行命令的前置检查即保存一个 `command` 节点
- **THEN** 不因缺少前置检查而拒绝保存(该字段可选)

#### Scenario: 填写空白前置检查被校验拦截
- **WHEN** 用户为某行命令的前置检查输入了空白内容并保存
- **THEN** 保存校验失败并提示前置检查命令不可为空(对齐 `workflow-definition` 校验)

### Requirement: 每条命令的可选超时编辑

工作流编辑器 SHALL 为每一处可执行命令提供一个可选**超时(秒)**输入:`command` 节点多命令列表的**每行命令**处、每道客观门把处、每个人工门把动作按钮处各有其独立的超时输入。该输入为可选(留空=无超时);填写时其值 MUST 经 `workflow-definition` 校验(正数)参与保存。编辑器 MUST NOT 设任何默认超时(全局默认无超时)。

#### Scenario: 命令与客观门可各设超时
- **WHEN** 用户编辑一个 `command` 节点某行命令及其客观门把
- **THEN** 该行命令处与该客观门把处各有独立可选超时输入,填写的正数值随定义保存、留空即无超时
