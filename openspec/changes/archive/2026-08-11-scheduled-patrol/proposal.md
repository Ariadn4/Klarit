## Why

「让项目规模化后不腐烂」是 Klarit 的产品主张，但现在**所有维护动作都是被动的**：文档归档挂在工作流尾部（`archive-docs`）、合规靠宪法与规则包在 agent 节点生效——都只在**跑需求卡时**才顺带发生。

于是没人跑需求的那段时间，没有任何东西在看着项目：文档跟代码漂移了、宪法里的规矩被违反了、依赖长毛了——都要等到下次有人开一张卡、而且恰好那张卡碰到了这块，才会被发现。**腐烂正是在没人干活的时候发生的**，这恰恰是我们唯一没有覆盖的时间段。

`todo-auto-scheduler` 证明了「主进程常驻回路自动干活」这个形态在本项目是成立的。缺的是一个**按时间而非按事件**触发的同类回路。

## What Changes

- **新增项目级定时巡检（patrol）**：一条巡检 = `{ id, 名字, 触发, 动作, 开关 }`，随项目配置持久化。用户可增删改、可单独停用而不删除。
- **触发用固定周期而非 cron 表达式**：`{ everyHours: n }` 或 `{ daily: 'HH:mm' }` 或 `{ weekly: { day, time } }`。不引入 cron 表达式——面向的是不读代码的用户，`0 3 * * 1` 不该出现在这个产品里。
- **动作三选一，全部收敛到既有接缝**：跑库里的某个**工作流** / 跑一条**命令**（复用 `command-execution` 的可取消运行器）/ 跑一次**文档腐烂扫描**（复用 `document-scan`）。不为巡检发明新的执行器。
- **巡检不自作主张改东西——主动产出只有一个去处**：经既有 `submitDecomposedCandidates` 接缝**推成候选需求卡**，**止于审阅**——不落库、不建分支、不自动排程（遵守既有「新建需求止于审阅」的边界）。

  巡检 MUST NOT 直接改代码、直接合并、直接建活卡。它的职责是**发现问题并转成需求**，改不改由用户决定。

  **巡检不往收件箱塞独立条目**：`decision-inbox` 是 `pendingDecision` 的纯投影，塞独立条目会破坏其不变量。巡检跑的工作流若停在人工门上，其运行**照既有决策机制**自然出现在收件箱——那是引擎行为，巡检侧零代码。
- **巡检占用自动排程的并发槽**：巡检启动的运行计入 `todo-auto-scheduler` 的并发上限（默认 3），槽满则**跳过本次、不排队**。避免巡检和自动排程互相抢仓、也避免定时任务堆积成雪崩。
- **软件没开就不跑，开机只补最近一次**：桌面应用的诚实边界。错过的窗口 MUST NOT 逐个补跑——开机时若某巡检自上次执行以来已错过至少一个窗口，只跑**一次**。

## Capabilities

### Added Capabilities
- `scheduled-patrol`: 巡检的模型（触发/动作/开关）与持久化、主进程常驻的定时回路与串行化、三类动作到既有接缝的映射、产出去处与「不自作主张」边界、并发槽共享与跳过、软件未开期间的补跑口径、设置界面。

### Modified Capabilities
- `todo-auto-scheduler`: 并发上限的口径从「自动排程启动的运行」扩为「自动排程 + 巡检启动的运行」——二者共享同一上限、同一活跃判定 `isRunLive`。手动启动仍不受此上限约束。

## Impact

- **依赖 / 复用**：与 `decision-inbox` 的关系是**零耦合**——巡检不调它、不写它，只是巡检拉起的工作流停在人工门时会被它投影到（引擎既有行为）。复用 `auto-scheduler` 的回路形态（串行化 `evaluate`、可重入合并、永不抛）、`command-execution` 的可取消运行器、`document-scan`、`engine.start`、`submitDecomposedCandidates` 接缝。
- **代码**：新增 `src/main/patrol-scheduler.ts`（常驻回路，与 `auto-scheduler.ts` 同风格同注入方式）+ `src/shared/patrol.ts`（触发计算与到期判定纯函数）；`src/main/project-service.ts`（巡检配置持久化）；`src/main/auto-scheduler.ts`（活跃计数纳入巡检运行）；渲染层新增巡检设置界面。
- **兼容**：巡检默认**一条都没有**——不预置任何巡检，不改变任何现有行为。用户不建巡检则本能力完全静默。
- **不在本 change**：cron 表达式、巡检结果的历史报表与趋势、跨项目巡检、巡检产出直接改代码或自动提 PR、软件未开时的后台常驻进程（那是另一个形态的产品决策）。
