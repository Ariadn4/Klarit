## ADDED Requirements

### Requirement: 带蒙层的浮层文件查看器

应用 SHALL 提供一个**文件查看器**：一个覆盖在**主面板区**之上、带半透明蒙层（遮罩）的浮层弹窗，用于**只读**查看文件内容。蒙层 MUST 限定在主面板区：**不跨到侧边栏**（侧边栏文件树在浮层打开时仍可见、可操作），且 **不覆盖常驻底栏**（见「常驻底栏（任务栏）」）——底栏与浮层共存、不互斥。点击蒙层空白处 MUST 收起浮层（蒙层+弹窗消失、底栏与已打开标签保留），而非整体关闭（避免误丢已打开的标签）。查看器未打开任何文件时，浮层与蒙层 MUST 不渲染（此时只剩常驻底栏）。

#### Scenario: 打开文件时浮层与蒙层出现
- **WHEN** 查看器收到打开某文件的请求且当前无任何已打开文件
- **THEN** 浮层弹窗与其蒙层出现在主面板区之上，展示该文件内容，蒙层不覆盖侧边栏

#### Scenario: 点击蒙层空白处收起浮层
- **WHEN** 查看器浮层处于展开态，用户点击浮层之外的蒙层区域
- **THEN** 浮层与蒙层收起，常驻底栏与已打开的标签保留，浮层可再次展开

#### Scenario: 浮层展开时侧边栏与底栏不被蒙层覆盖
- **WHEN** 查看器浮层处于展开态
- **THEN** 蒙层只暗化主面板区，侧边栏与主面板底栏仍清晰可见、可点击

#### Scenario: 无打开文件时只剩常驻底栏
- **WHEN** 查看器没有任何已打开的文件
- **THEN** 主面板区不出现浮层与蒙层，仅保留常驻底栏

### Requirement: 通用的「打开文件」入口

文件查看器 SHALL 暴露一个**通用的打开文件 API**，以「文件的绝对路径」为唯一必需入参，不绑定任何特定调用方。文件树点击 MUST 通过该 API 打开文件；该 API MUST 设计为可供未来其它入口（如 agent 提及、需求卡附件、产出物）复用。重复打开**同一路径**的文件 MUST 不新增标签，而是聚焦到已存在的那个标签。

#### Scenario: 通过通用 API 打开一个文件
- **WHEN** 任意调用方以一个文件绝对路径调用打开文件 API
- **THEN** 查看器展开（若处于最小化或未打开），新增或聚焦到该文件对应的标签并展示其内容

#### Scenario: 重复打开同一文件聚焦既有标签
- **WHEN** 某文件已在查看器中打开，再次以同一路径请求打开
- **THEN** 不新增标签，查看器聚焦到该文件已有的标签

### Requirement: 多文件标签页

文件查看器 SHALL 支持**同时打开多个文件**，每个文件以一个**标签页**呈现，标签横向并列于查看器顶部。标签 MUST 显示文件名，当前激活标签 MUST 有明确的选中视觉。点击某标签 MUST 切换内容区到该文件。每个标签 MUST 提供单独的关闭控件，关闭一个标签只移除该文件、不影响其它标签。

#### Scenario: 打开多个文件形成多个标签
- **WHEN** 用户先后打开两个不同路径的文件
- **THEN** 查看器顶部出现两个标签，内容区展示最后打开（激活）的那个文件

#### Scenario: 点标签切换文件
- **WHEN** 查看器有多个标签，用户点击非激活的某个标签
- **THEN** 该标签变为激活态，内容区切换为该文件内容

#### Scenario: 关闭单个标签
- **WHEN** 查看器有多个标签，用户点击某标签的关闭控件
- **THEN** 该标签及其文件被移除，其余标签保留；若关闭的是激活标签，则激活相邻的一个标签

#### Scenario: 关闭最后一个标签收起查看器
- **WHEN** 查看器仅剩一个标签，用户关闭它
- **THEN** 查看器不再有打开的文件，浮层、蒙层与底栏均消失

### Requirement: 常驻底栏（任务栏）

主面板区底部 SHALL 有一条**常驻底栏**，类似 Windows 任务栏：它**一直显示**（即便没有任何已打开文件），限定在主面板区（不跨侧边栏），且**不被蒙层覆盖**——与浮层共存、不互斥。底栏**不**以整条作为入口，而是当有已打开文件时，在其上放一个 `square-menu` 图标 + 已打开文件数量作为唯一开合入口。点击该入口 MUST 在「展开浮层」与「收起浮层」之间切换；切换不影响已打开的标签与激活项。没有已打开文件时入口 MUST 不出现（底栏仍在）。

#### Scenario: 底栏始终显示
- **WHEN** 查看器没有任何已打开文件
- **THEN** 主面板区底部仍显示常驻底栏，只是其上没有开合入口

#### Scenario: 有打开文件时底栏给出入口
- **WHEN** 查看器有若干已打开文件
- **THEN** 底栏上出现 `square-menu` 图标 + 文件数量入口

#### Scenario: 点击底栏入口收起展开的浮层
- **WHEN** 浮层处于展开态，用户点击底栏入口
- **THEN** 浮层与蒙层收起，底栏与所有标签、激活项保留

#### Scenario: 点击底栏入口展开已收起的浮层
- **WHEN** 浮层处于收起态且有已打开文件，用户点击底栏入口
- **THEN** 浮层与蒙层重新出现，恢复到收起前激活的标签

### Requirement: 整体关闭查看器

文件查看器 SHALL 提供一个**整体关闭**控件，关闭后清空所有标签、移除浮层/蒙层/底栏，查看器回到「未打开任何文件」的初始态。

#### Scenario: 整体关闭清空所有标签
- **WHEN** 查看器有多个已打开文件，用户点击整体关闭控件
- **THEN** 所有标签被清空，浮层、蒙层与底栏全部消失

### Requirement: 只读内容渲染

文件查看器的内容区 SHALL 以 **monaco（只读模式）** 渲染文本类文件，并根据文件扩展名提供语法高亮；内容 MUST 不可编辑。对于无法以文本安全展示的文件，查看器 MUST 做降级处理而非把原始字节喂给 monaco：

- 二进制文件 MUST 显示「无法以文本预览」的占位提示（不渲染乱码）。
- 超过大小上限的文件 MUST 显示「文件过大，不予预览」的占位提示。
- 读取失败（如文件已被删除/无权限）MUST 显示错误提示，且不影响其它标签。

文件内容 MUST 经主进程只读读取（见「主进程只读读取文件」），渲染层不直接访问磁盘。

#### Scenario: 文本文件带语法高亮渲染
- **WHEN** 用户打开一个文本类源码文件
- **THEN** 内容区以 monaco 只读模式展示其内容，并按文件类型应用语法高亮，用户无法编辑

#### Scenario: 二进制文件降级提示
- **WHEN** 用户打开一个二进制文件
- **THEN** 内容区显示「无法以文本预览」的占位提示，不渲染原始字节

#### Scenario: 超大文件降级提示
- **WHEN** 用户打开一个超过预览大小上限的文件
- **THEN** 内容区显示「文件过大，不予预览」的占位提示

#### Scenario: 读取失败提示
- **WHEN** 某标签对应的文件读取失败（已删除或无权限）
- **THEN** 该标签内容区显示错误提示，其它标签不受影响

### Requirement: 主进程只读读取文件

主进程 SHALL 提供一个**只读**读取文件内容的 IPC 契约，经 preload 暴露给渲染层（如 `readFile(path)`）。该契约 MUST 仅读取、不写入；MUST 对超过大小上限的文件拒绝返回完整内容（返回「过大」信号）；MUST 能区分二进制与文本（返回相应信号或标记），以便渲染层降级。

#### Scenario: 读取文本文件返回内容
- **WHEN** 渲染层以一个文本文件绝对路径调用 readFile
- **THEN** 主进程返回该文件的文本内容供查看器渲染

#### Scenario: 超大文件不返回完整内容
- **WHEN** 渲染层请求读取一个超过大小上限的文件
- **THEN** 主进程不返回完整内容，而是返回「文件过大」信号

#### Scenario: 二进制文件标记返回
- **WHEN** 渲染层请求读取一个二进制文件
- **THEN** 主进程返回「二进制」标记而非文本内容
