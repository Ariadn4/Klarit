## Why

现在点击文件树里的文件没有任何反应——用户看得到文件却打不开，想确认某个产出物或文档的内容只能跳出软件去外部编辑器。Klarit 的主路径是在需求层操作、查看代码是兜底，但这个兜底当前完全缺失。同时，未来 agent 提及、需求卡附件、产出物等多个入口都需要「打开并查看某个文件」这一能力，应当一次性建成一个可复用的查看器，而不是各处各做一套。

## What Changes

- 新增**文件查看器**：一个带蒙层（遮罩）的浮层弹窗，用于查看文件内容（**只读**）。
- 文件树的文件项**可点击打开**：点击文件树里任意文件，在查看器中打开它（点击文件夹仍是展开/折叠，行为不变）。
- 查看器**支持多开**：同时打开多个文件，以**标签页**形式并列，点标签切换、每个标签可单独关闭。
- 查看器可**最小化到主窗口底栏**：收起浮层与蒙层、在主窗口底部留一个常驻条，点击底栏可重新展开；也可**整体关闭**（清空所有标签）。
- 文件内容用 **monaco（只读模式）** 渲染，带语法高亮；二进制/图片/超大文件做降级处理（不喂给 monaco）。
- 查看器的打开入口设计为**通用 API**：以「打开某绝对路径文件」为唯一入参，供文件树调用，也供未来 agent 提及、需求卡附件/产出物等入口复用。
- 新增主进程 **读取文件内容** 的 IPC（只读），经 preload 暴露给渲染层。

非目标（本次不做）：编辑与保存、文件的重命名/删除、跨窗口同步查看器状态、目录的打开。

## Capabilities

### New Capabilities
- `file-viewer`: 带蒙层的浮层文件查看器——多文件标签页、最小化到底栏/关闭、只读内容渲染（monaco），以及供任意入口复用的通用「打开文件」API 与主进程只读读取文件的契约。

### Modified Capabilities
- `app-shell-sidebar`: 文件树的「文件项点击行为」由当前的无响应，变更为**点击文件打开文件查看器**（文件夹的展开/折叠行为不变）。

## Impact

- 渲染层：新增查看器组件（浮层 + 蒙层 + 标签页 + 底栏 + monaco 内容区）与一个全局查看器状态（zustand store，承载「打开/关闭/切换/最小化」与已开文件列表）；`FileTree` 的文件项接上点击 → 调用 store 打开；`App` 挂载查看器浮层与底栏。
- 主进程 / 契约：`src/shared/ipc.ts` 新增 `fs:readFile` 通道；`src/main/index.ts` 新增只读读取 handler（含大小上限与二进制判定）；`src/preload/index.ts` 与 `src/shared/types.ts`（`KlaritApi`）新增 `readFile`。
- 依赖：新增 `monaco-editor`（及 Electron/electron-vite 下的 worker 接入配置）。
- UI：遵循 `docs/brand/klarit-brand-system.html` 的浮层/蒙层规范，不另起配色或投影。
