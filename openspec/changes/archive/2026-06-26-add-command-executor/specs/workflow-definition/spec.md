## ADDED Requirements

### Requirement: command 执行者的前置检查命令

`command` 执行者 SHALL 支持一条可选**前置检查命令**(`check`):一个 CLI 命令字符串,表达「本命令是否已完成」的探测(退出码 0=已完成)。该字段供引擎在执行主命令前做 reconcile-by-probe(见 `engine-execution`「命令节点的前置检查护栏」),让不幂等命令在中断恢复时不重复执行。`command` 执行者 MAY 不声明该字段。

该字段为**可选**且为**向后兼容增量**:未声明的 `command` 节点(含既有工作流包)照常加载、行为不变、读写往返一致。声明时其结构校验为:`check` 命令字符串 MUST 非空(同 `inline` 客观门把命令的约束);命令是否在某机器上可成功执行**不在校验内强制**(属引擎运行期)。`check` 与主命令 `command` 一样为待执行的 CLI 串,不施加产出/可写范围那样的相对路径约束。

#### Scenario: 声明前置检查命令往返保持
- **WHEN** 某 `command` 节点声明 `check` 并保存后读回
- **THEN** `check` 命令字符串完整保留在定义中

#### Scenario: 未声明前置检查的命令节点照常合法
- **WHEN** 加载/保存一个未声明 `check` 的 `command` 节点(含既有工作流包)
- **THEN** 定义合法、可读回,行为与未引入该字段时一致

#### Scenario: 空前置检查命令被拒
- **WHEN** 某 `command` 节点声明了 `check` 但其命令字符串为空
- **THEN** 结构校验失败、定义不被保存,并返回指明 `check` 命令为空的原因

### Requirement: 每条命令的可选超时字段

工作流定义中**每一处被执行的命令** SHALL 支持一个可选**超时秒数**(`timeoutSec`):`command` 执行者的主命令、客观(`auto`)门把项、人工门把的动作按钮各可携带 `timeoutSec`。该字段为**可选**且为**向后兼容增量**——未声明即无超时(全局默认无超时),既有工作流包照常加载、读写往返一致。声明时其结构校验为:`timeoutSec` MUST 为**正数**(`> 0`);非正数或非数值判为非法。该超时为每条命令独立(同节点主命令与客观门可设不同值),`ref` 形态客观门的超时落在**门把使用点**而非规则库条目。

#### Scenario: 声明超时往返保持
- **WHEN** 某命令节点主命令(或客观门、动作)声明 `timeoutSec` 并保存后读回
- **THEN** 该超时值完整保留在定义中

#### Scenario: 未声明超时照常合法
- **WHEN** 加载/保存一处未声明 `timeoutSec` 的命令(含既有工作流包)
- **THEN** 定义合法、可读回,视为无超时,行为与未引入该字段时一致

#### Scenario: 非正数超时被拒
- **WHEN** 某处命令声明的 `timeoutSec` 为 0、负数或非数值
- **THEN** 结构校验失败、定义不被保存,并返回指明超时须为正数的原因
