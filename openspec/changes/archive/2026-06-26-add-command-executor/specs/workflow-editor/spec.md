## ADDED Requirements

### Requirement: command 节点的前置检查命令编辑与软提示

`command` 执行者节点的设置块 SHALL 提供一个可选**前置检查命令**输入(对应 `workflow-definition` 的 `check` 字段),并在其旁呈现一段**软提示**,引导作者为不幂等命令补上前置检查,以避免中断恢复时重复执行。该提示为**纯引导**——编辑器 MUST NOT 强制要求填写前置检查(系统无法可靠判别命令是否幂等),仅在用户填写后按 `workflow-definition` 的结构校验(声明则非空)参与保存校验。

软提示文案 SHALL 以「非幂等命令(跑一次生效后重跑会重复或产生副作用,如数据库迁移、版本号自增、发送通知等)建议加前置检查」为意,**不以部署/发布为例**(该类引导走引擎操作)。提示文案为 i18n、随语言切换。

#### Scenario: command 节点呈现前置检查输入与提示
- **WHEN** 用户打开一个 `command` 执行者节点的详情
- **THEN** 呈现「命令」与可选「前置检查命令」输入,且前置检查旁有引导软提示

#### Scenario: 前置检查为可选不阻塞保存
- **WHEN** 用户未填写前置检查命令即保存一个 `command` 节点
- **THEN** 不因缺少前置检查而拒绝保存(该字段可选)

#### Scenario: 填写空白前置检查被校验拦截
- **WHEN** 用户为 `command` 节点的前置检查输入了空白内容并保存
- **THEN** 保存校验失败并提示前置检查命令不可为空(对齐 `workflow-definition` 校验)

### Requirement: 每条命令的可选超时编辑

工作流编辑器 SHALL 为每一处可执行命令提供一个可选**超时(秒)**输入:`command` 节点主命令处、每道客观门把处、每个人工门把动作按钮处各有其独立的超时输入。该输入为可选(留空=无超时);填写时其值 MUST 经 `workflow-definition` 校验(正数)参与保存。编辑器 MUST NOT 设任何默认超时(全局默认无超时)。

#### Scenario: 各命令处呈现独立超时输入
- **WHEN** 用户编辑一个 `command` 节点及其客观门把
- **THEN** 主命令与客观门把各有独立的可选「超时(秒)」输入,可分别设不同值或留空

#### Scenario: 超时留空即无限制
- **WHEN** 用户不填某命令的超时即保存
- **THEN** 该命令视为无超时,保存不被阻塞
