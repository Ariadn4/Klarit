## ADDED Requirements

### Requirement: 全局对话面板作为永远可用的用户头牌入口

系统 SHALL 提供一个**常驻的全局对话面板**，作为用户直接跟全局 agent 多轮聊「我想要什么」的头牌入口。该入口 SHALL **无需绑定任何项目即可打开、agent 随时可起**——用户把它当作单一、随时可开的全局入口，不预设「当前在哪个项目」，会混着提当前项目的需求与「要做个新东西」的新项目需求，不必为发起 agent 专门开一个空项目窗口。用户在面板里输入自由意图（如「我想要 X」/「把 A、B 合并」/「这卡拆两半」/「我要做个新工具」），系统 SHALL 经编排核 `orchestrate` 推理、产出提案并交审阅流。该面板 SHALL 与现有「待办列 + 创建·描述想法」入口**并列保留、共用同一编排核**（不各自实现一套产出逻辑）。面板入口 SHALL 落在主面板**常驻底栏**，遵 `docs/brand` 与设计令牌（仅用语义令牌、深浅双主题）。

#### Scenario: 未绑定项目也能开面板并对话

- **WHEN** 当前窗口未绑定任何项目，用户点击全局对话入口
- **THEN** 面板照常打开、可输入意图并跟 agent 对话，不静默无反应、不报错

#### Scenario: 用户经对话面板发起编排

- **WHEN** 用户在全局对话面板输入一段自由意图并提交
- **THEN** 系统经编排核产出提案，并把提案交审阅流呈现

#### Scenario: 与描述想法入口共核

- **WHEN** 用户分别经「描述想法」快速建卡与全局对话面板发起
- **THEN** 两者共用同一编排核，「描述想法」等价于以 create 偏置的一次编排

### Requirement: 对话会话按项目分开持久化到 userData

系统 SHALL 把项目 Agent 的**会话按项目分开持久化到用户数据目录**（`userData`，不入 git，随云同步走）——每条会话**归属它所在窗口当前绑定的项目**（`userData/conversations/<projectId>/<id>.json`）；**未绑定任何项目**的窗口用一个**独立的未绑定作用域**（`__unbound__`）。每条会话至少存**有序消息历史**（用户意图与 agent 答复/提案）与**最近一次 agent 会话 id**（供原生续接）。关闭面板或重开应用后，会话 MUST 可被该项目读回并继续。

在某项目窗口打开 Agent 时，MUST 只列出/续用**该项目**的会话（看不到别的项目、也看不到未绑定作用域的会话）；因此在**不同项目窗口**打开 Agent 看到的是**各自项目的会话**，不串。**新项目/无既有会话**时，打开即开一条新对话。

#### Scenario: 会话按项目隔离

- **WHEN** 在项目 A 窗口聊若干轮，再在项目 B 窗口打开 Agent
- **THEN** B 窗口只看到 B 自己的会话（看不到 A 的），A 的会话在 A 窗口仍可读回续用

#### Scenario: 新项目窗口开新对话

- **WHEN** 在一个尚无会话的项目（或刚创建的新项目）窗口打开 Agent
- **THEN** 直接开一条新对话，不串入别的项目或未绑定作用域的旧会话

#### Scenario: 未绑定窗口用独立作用域

- **WHEN** 在未绑定项目的窗口聊天
- **THEN** 会话落在独立的未绑定作用域，不与任何项目的会话混在一起

### Requirement: 全局对话可按会话选 agent 与模型

系统 SHALL 允许用户在全局对话面板**按会话**选用驱动全局 agent 的**编程 agent（外壳）与模型**，**覆盖全局默认**（`settings.defaultAgent`/`defaultModel`）；未选择时 MUST 回落全局默认（默认解析在主进程）。可选项 SHALL 取自**静态受支持 agent 清单**（`listSupportedAgents`，各 agent 带其静态模型表），使选项**永远非空、不依赖 CLI 探测**；模型下拉含一项「默认模型」（值为空、表示不覆盖、用全局默认）。该选择 MUST 随会话**持久化**（存于 `Conversation`），重开/续接后仍生效；同一会话的后续轮次 SHALL 用该会话选定的 agent/模型驱动编排。

#### Scenario: 选模型后本会话用该模型

- **WHEN** 用户在某会话选了某 agent 的某模型并发起编排
- **THEN** 该会话的编排用所选 agent/模型驱动，而非全局默认

#### Scenario: 未选则回落全局默认

- **WHEN** 会话未选 agent/模型
- **THEN** 编排回落 `settings.defaultAgent`/`defaultModel`

#### Scenario: 选择随会话持久化

- **WHEN** 选定 agent/模型后关闭面板、重开该会话
- **THEN** 该会话仍记住所选 agent/模型

### Requirement: 聊天内容可复制

系统 SHALL 让全局对话的消息内容**可复制**：消息文字 SHALL **可选中**（覆盖 app 全局禁选）。**右键一条消息** SHALL 弹出上下文菜单，含「复制该消息」（复制整条消息的文字，agent 消息含其回复与提案的可读描述）；当存在非空文字选区时，菜单 SHALL 另含「复制选中的文字」（复制当前选区文本）。复制 MUST 复用既有剪贴板通道（`copyText`）。菜单 SHALL 可经点击菜单外或 Esc 关闭。

#### Scenario: 右键消息复制整条

- **WHEN** 用户右键一条消息、点「复制该消息」
- **THEN** 该消息文字写入系统剪贴板

#### Scenario: 选中文字后右键复制选区

- **WHEN** 用户选中消息里一段文字、右键点「复制选中的文字」
- **THEN** 所选文本写入系统剪贴板

#### Scenario: 无选区时不显示复制选中

- **WHEN** 无文字选区时右键消息
- **THEN** 菜单只含「复制该消息」，不含「复制选中的文字」

### Requirement: 消息底部操作（复制 / 编辑 / 重试）

系统 SHALL 在每条消息底部提供操作按钮：

- **用户消息**：始终有「复制」（复制该消息文字）；**仅最新一条用户消息**另有「编辑」与「重试」。「编辑」把该消息文字回填输入框、并**移除该轮（该用户消息及其后的 agent 回复一并消失）**，供修改后重发。「重试」**丢弃该轮的 agent 回复、按本会话选型重跑该条用户意图**，替换而非追加。
- **agent 消息**：只有「复制」。

agent 回复**为空**（无文字、无提案）时 MUST NOT 再显示「本轮没有产出内容」占位气泡——历史里没输出的轮次不留占位；用户可用「重试」重来。

#### Scenario: 复制任一消息

- **WHEN** 点击某条消息底部的「复制」
- **THEN** 该消息文字写入剪贴板

#### Scenario: 编辑最新用户消息

- **WHEN** 点击最新用户消息的「编辑」
- **THEN** 其文字回填输入框、该轮从会话移除，供修改后重新发送

#### Scenario: 编辑连带删除该轮 agent 回复

- **WHEN** 点击最新用户消息的「编辑」
- **THEN** 该用户消息**及其后的 agent 回复一并从对话消失**，文字回填输入框供修改后重发

#### Scenario: 重试最新用户消息

- **WHEN** 点击最新用户消息的「重试」
- **THEN** 系统丢弃该轮 agent 回复、按本会话选型重跑该条用户意图，用新回复替换（不追加多一轮）

#### Scenario: 空回复不留占位

- **WHEN** 某轮 agent 回复为空（无文字无提案）
- **THEN** 不显示「本轮没有产出内容」占位气泡

### Requirement: 全局对话可多开

系统 SHALL 支持**多条全局对话并发存在**（对齐三层结构中全局 agent「可多开」）：用户可开多个全局对话面板/标签，各自 MUST 持有**独立的会话上下文与历史**，互不串扰。每条会话 MUST 有稳定标识（`conversationId`），供持久化、续接与 UI 切换。

#### Scenario: 多条会话独立

- **WHEN** 用户同时开两条全局对话，各自聊不同意图
- **THEN** 两条会话历史独立、互不污染，各自经编排核推理

#### Scenario: 会话标识稳定

- **WHEN** 一条会话被持久化后重新载入
- **THEN** 它按稳定 conversationId 被识别、续上原历史

### Requirement: 全局对话多轮经续接接上

系统 SHALL 让全局对话的多轮走**原生续接**优先的阶梯：有会话 id 且外壳支持 `--resume` 时接上真实会话（带记忆）；不支持或续接失败时回落**用自存消息历史重建上下文**新起一轮。此续接逻辑 SHALL 复用既有的续接阶梯（`launchContinuation`/`buildContinuationDelta` 一类，不为全局对话另造一套）。

#### Scenario: 原生续接接上会话

- **WHEN** 会话已有 agent 会话 id 且外壳支持原生续接
- **THEN** 下一轮经 `--resume <id>` 接上带记忆的会话

#### Scenario: 续接失败回落历史重建

- **WHEN** 无会话 id 或原生续接拉起失败
- **THEN** 系统用自存消息历史重建上下文、新起一轮，不中断对话
