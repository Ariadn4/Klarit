## ADDED Requirements

### Requirement: 工作流软校验——结构可判反模式的非阻断告警

系统 SHALL 提供一层**工作流软校验**(比照 `checkBranchPairing` 的「可加载但有隐患」定位):对**结构上可判**的反模式给出**非阻断告警**,经 `WorkflowSummary`(`invalidReason` 或并列的告警字段)在编辑器/选择器露出。软校验 MUST NOT 阻断存库或加载,`validateWorkflow` 的硬校验语义不变。软校验覆盖两路来源——**agent 生成**与**用户手动编辑**——因为它作用于最终工作流定义本身,与定义从何而来无关。

软校验**只纳入结构可判的反模式**。判据依赖自由命令文本内容的(如「期望失败的红门」:`auto` 门通过条件写死为退出码 0、无取反字段,取反只能藏进命令字符串)**不纳入**——无法可靠识别。

#### Scenario: 软校验非阻断、经摘要露出

- **WHEN** 一份工作流触发某条软校验
- **THEN** 系统给出可读告警并经 `WorkflowSummary` 露出,但**不**阻断该工作流存库/加载

#### Scenario: 手动改乱同样被软校验兜住

- **WHEN** 用户在编辑器里手动把工作流改成某个结构可判的反模式
- **THEN** 软校验照样告警(不因来源是手动而放过)

#### Scenario: 红门不纳入软校验

- **WHEN** 某 `auto` 门的命令文本里藏了取反以表达「必须失败」
- **THEN** 软校验不试图识别它(判据依赖自由命令内容、不可靠),仅由 skill 的 prompt 约束劝阻

### Requirement: 软校验首条——不可逆固化操作之前(含其上)须有人工门

工作流软校验 SHALL 含一条:若工作流存在**不可逆固化**引擎操作,而按**节点执行顺序**在**第一个**固化操作**之前或就挂在该固化节点自身上**都**没有任何 `manual` 门**,则告警「固化步骤前缺人工验收」。判据纯结构(执行序 + 固化操作集 + 门类),不看命令文本。

**固化操作集**从引擎操作能力单一来源(`finalizesIrreversibly`)派生,限于**让改动离开可回退工作区、难以收回**者:`merge-branch`(并入主线)、`push-branch`(推送远端)、`open-pr`(对外公开)。`archive-docs` **不属**固化——它把文档提交到**特性分支/worktree**,合入前驳回即随分支丢弃、**可回退**,故不纳入此判据。

**挂在固化节点自身上的 `manual` 门计入**:把人工评审门挂在 `push-branch`/`merge-branch`/`open-pr` 节点上(该门在其动作生效前拦一道人来拍板)是正规打法,不应误报;因此判据取「第一个固化节点**及其之前**」范围内是否有 `manual` 门。

#### Scenario: 固化前(含其上)无人工门 → 告警

- **WHEN** 工作流的第一个固化操作(`merge-branch`/`push-branch`/`open-pr`)之前及该节点自身都没有任何 `manual` 门
- **THEN** 软校验告警「固化步骤前缺人工验收」

#### Scenario: 人工门挂在固化节点自身上 → 不告警

- **WHEN** 某 `manual` 门就挂在第一个固化节点(如 `push-branch`)上
- **THEN** 该条软校验不告警(该门在固化动作生效前拦一道人)

#### Scenario: 人工门排在固化之前 → 不告警

- **WHEN** 某 `manual` 门在执行序上排在第一个固化操作之前
- **THEN** 该条软校验不告警

#### Scenario: archive-docs 不算固化,单它不触发

- **WHEN** 工作流含 `archive-docs` 但不含 `merge-branch`/`push-branch`/`open-pr`
- **THEN** 该条软校验不适用、不告警(archive-docs 可回退,不属固化)

#### Scenario: 无固化操作 → 不适用

- **WHEN** 工作流不含任何不可逆固化引擎操作
- **THEN** 该条软校验不适用、不告警

### Requirement: 内置默认工作流须在固化前含人工审批门,措辞不宣示"无人值守"

「重大/不可逆步骤须人工审批」是产品硬原则。内置**默认(本地直合)工作流** SHALL 在不可逆固化(合并回主干)之前含一道 `manual` 审批门,使其**自身通过固化门 lint**、并以结构体现该原则(而非仅在描述里说)。其显示名/描述 MUST NOT 宣示「无人值守 / unattended / 免审批自主跑完」这类与原则冲突的措辞;"本地直合"作为**合并策略名**(本地合并 vs PR 合并)保留。

#### Scenario: 默认工作流含固化前审批门、过 lint

- **WHEN** 取内置默认(本地直合)工作流并跑 `lintWorkflow`
- **THEN** 它在合并前含 `manual` 审批门、无「固化前缺人工验收」告警

#### Scenario: 默认工作流描述不宣示无人值守

- **WHEN** 查看内置默认工作流的显示名与描述
- **THEN** 不含「无人值守/unattended/免审批」等与"重大步骤须审批"冲突的措辞
