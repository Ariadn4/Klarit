## Why

任务详情抽屉与卡面对同一张卡「说两套话」：卡面有运行圆点+节点文案、有可点跳 git 视图的分支条目；抽屉却只有一行 `状态 · 预取名`——那行的名字还是**预取名**（撞名递增后可能与引擎实际分支不符），既不能点、也看不出运行进度。用户想在抽屉里也能一眼看进度、点分支跳 git 视图，且打开有分支的卡时侧栏能自动带到对应分支。同时运行主控点下去到引擎响应之间是空窗，缺个过渡态。

## What Changes

- **抽屉运行进度**：抽屉头部改为展示与卡面**完全一致**的运行圆点 + 节点文案 + 细状态（工作中/检查中/等待决策）+ 暂停图标；无运行时回落生命周期状态文案。**删除**现有「`t(状态) · proposedName`」那行。
- **抽屉可点分支**：抽屉展示该卡各成员仓**已建出分支**的条目（复用卡面 `cardBranches` 口径与「成员仓名/分支名」标签），点击后侧栏切 git 视图并聚焦到 (该成员仓, 该分支)——与卡面条目行为一致（判定门控为「分支已建」，不看盘上 worktree）。
- **打开详情联动 git 视图**：打开一张已建出分支的卡详情时，**仅当侧栏当前没在显示该分支**，自动把侧栏切到 git 视图并聚焦到**默认第一个成员仓**的分支；侧栏已在显示该分支则不打扰。
- **运行主控 loading 过渡**：运行/暂停/恢复为异步 IPC，点击后到引擎兑现之间，主控按钮 SHALL 进入 loading 态（转圈图标 + 禁用），兑现后复位，避免空窗死点。

## Impact

- 渲染层：`RequirementCardDetail.tsx`（头部改造、新增分支条目、主控 loading）、`RequirementCardView.tsx`（抽出共享块）、`stores/cards.ts`（`openDetail` 需侧栏联动，或在抽屉打开副作用里做）、`App.tsx` 侧栏 view 状态是「当前是否已在显示该分支」的判据来源。
- 建议抽取共享组件：卡面内联的运行状态块（圆点+文案+细状态+暂停图标）与分支条目块（chip + 点击 `focusCardGitView`）抽成共享组件供卡面与抽屉复用，避免两处分叉。纯实现，不改契约。
- 复用既有 IPC：`cardBranches`、`focusCardGitView`、`pauseRun`/`resumeRun`/`runCard`；`runDot`/`<RunDot>`（`lib/board.ts`）。无新增主进程 IPC。
