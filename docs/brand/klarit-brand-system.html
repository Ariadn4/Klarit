08 — INTERACTION · FOCUS · MOTION

交互硬规则

源自 Vercel Web Interface Guidelines，按 Klarit 桌面端（Electron + React）裁剪。这些是可达性与一致性的底线，所有界面通用。

FOCUS & KEYBOARD
规则做法
可见焦点所有可聚焦元素显示焦点环，优先 :focus-visible（键盘才显示，鼠标点击不显示）；环用 cobalt-500、offset 2px
键盘可达全流程可仅用键盘完成，遵循 WAI-ARIA 模式；自定义「可点」元素（如行内编辑只读块）须 tabindex=0 + 角色 + Enter/Space 触发
焦点管理模态 / 抽屉 / 菜单：进入移焦并陷阱、关闭归还焦点；Esc 关闭（设置面板已做）
命中区 ≥24px视觉更小的图标也要把可点区域扩到 ≥24px；icon-btn 26×26 已满足
无死区看着可交互就要可交互；勾选/单选的 label 与控件共享单一命中区
主输入 autofocus桌面端、单一主输入时可 autofocus 提速
STATES：HOVER · ACTIVE · DISABLED · LOADING
态规则
hover / active / focus对比度高于静息态（更深的边/底/字）
禁用 disabledopacity 降低 + cursor: default + 不响应 hover；与「加载中」区分开
按钮加载保留原文案 + 加载指示；show-delay ~150–300ms、最短可见 ~300–500ms 防闪
进行中文案将打开输入或进行中的动作用省略号：「重命名…」「保存中…」
tooltip 时序首个延迟出现；相邻同组随后无延迟
DRAG & MOTION
规则做法
拖拽拖拽期间 user-select:none 并对内容用 inert；拖前自动提交编辑、收起展开行（见第 12 章行为速查）
滚动边界模态 / 抽屉内 overscroll-behavior: contain
只动廉价属性只过渡 transform / opacity；避开触发重排的 width/height/top/left
禁 transition: all显式列出要过渡的属性（本规范 .btn 已改正）
有意义且可打断仅当动画澄清因果或有意取悦时才用；可被用户输入打断；不自动播放；transform-origin 锚定起点
prefers-reduced-motion提供降级；本规范已加全局兜底 @media (prefers-reduced-motion: reduce)

09 — FORMS & INPUTS（行为）

输入控件的行为规范

视觉样式见 06 COMPONENTS；字段标签/描述类型对、列表编辑器、逐块行内编辑、多级嵌套的完整规范与图例见 第 12 章。下列为通用表单行为。

规则做法
标签无处不在每个控件有 <label> 或 aria-label；点 label 聚焦控件
提交键输入为唯一控件时 Enter 提交；textarea 用 ⌘/⌃+Enter 提交、Enter 换行
提交按钮保持可用直到提交开始再禁用；不因未填完就预先禁用——让用户提交以触发校验
不拦键入即便只接受数字也允许输入，再做校验反馈；不禁用粘贴；允许粘贴一次性验证码
错误就近显示在字段处；提交时聚焦第一个错误；校验/toast 用 aria-live="polite" 播报
类型与输入法正确的 type 与 inputmode；邮箱/代码/用户名关 spellcheck；设 autocomplete 与有意义的 name；搜索框 autocomplete="off"
placeholder以省略号结尾、给示例值（如 +1 (123) 456-7890）；不替代 label
未保存改动离开/关闭前若可能丢数据要警告
原生 select 深色显式设 color/background（项目用 color-scheme 已处理）

11 — ACCESSIBILITY & PERFORMANCE

可达性与性能

ACCESSIBILITY
规则做法
语义优先先用原生元素，再上 aria-*；标题层级 h1–h6 正确；导航用 <a> 不用 button/div

行为速查
行为规则
拖拽与展开互斥可拖拽排序的列表不得内联展开编辑，反之亦然。同时存在会导致拖拽时的收起/reflow 把行挪走、光标与目标错位。二选一：① 列表项可拖拽 → 行只读、点击进入独立详情视图编辑（外层只留只读摘要）；② 列表项内联展开/编辑 → 不提供拖拽排序（如需排序用 ▲▼）。
编辑入口字段少的简单项：行内逐块编辑（见上）。字段多的项（工作流节点、需求卡类型等）：用独立详情视图，列表行只读、行尾放一个「编辑」铅笔图标按钮进入详情——不要整行点击进入。详情顶栏用统一返回 chevron + 保存（见「详情返回」）。
铅笔 vs chevron（两种 affordance 不混用）铅笔（Pencil）= 进入独立详情页；chevron = 就地展开/收起。一个列表只用其中一种语义，不得用铅笔却做成展开、或反之。字段多的项一律走铅笔→详情页（详情页内可再放第二级子列表）。
双信息行一行需同时显示两条信息时（如 节点名 + 阶段名），主信息用 13/ink、次信息紧随其后用 12/stone-600（次要色小字）；主在前、次在后，二者间留白分隔，次信息不可编辑。不得随意排布。
字重层级分区/列表标题用 13/600（semibold）；行内项名（条目摘要名，如规则名、节点名）用 13/500（medium）——不要和分区标题同为 600，否则项名与标题视觉打架。正文/描述 400。
设置界面每行单输入设置界面内每行最多一个输入框：禁止并列输入框（如「名称+阶段+类型」「工具+模型」「文案+命令」）。每个字段各占一行（label→description→控件）。注：此约束限设置界面，软件其它区域可能并列。
点击编辑 vs 常存输入不混用同一个项（item/表单）内不得混用「点击编辑（read-only→点击变输入）」与「常存控件」。判定：若该项含任何常存控件（单选/复选/下拉/常显输入），则该项的所有字段都必须是常存输入框——其中的文本字段不能做成点击编辑。点击编辑只用于纯单值列表（每行只有一个可编辑值、无其它控件，如阶段名、可写路径）。反例：产出项里路径用点击编辑、却与「模板单选/必选复选」并存 → 路径须改为常存输入框。
详情返回 / 详情顶栏所有设置/详情/编辑视图共用同一套顶栏：左 返回 chevron 图标按钮（无文字，h-7）、右 保存（紧凑主按钮 h-7，与返回等高）+「已保存」提示。该顶栏与模态「关闭(X)」同一行（内部视图把 返回/保存 传送到模态顶栏插槽）；不得各处自画返回/保存——必须复用统一组件。保存按钮为紧凑高度，不要用偏高的 py-1.5。
排序可排序列表（阶段、节点）只放拖拽柄、不显序号——顺序由位置表达。拖拽柄为主、▲▼ 为次（少量项/纯点击），二者择一。非排序的纯标号列表（如可写范围/产出）可保留 #N 行号。
加 / 空 / 计数「加」是末行小按钮（左对齐、hover 用半透明 cobalt 以适配米黄 paper 底，只高亮自身）；空列表只剩 头(标题·描述·分割线)+加末行、无占位文案、无空盒；计数 badge 仅 >0 显示
库列表（managed）工作流库 / 需求卡类型 / 规则库这类「库」列表与普通列表同构：同一个头（标题 13/600 + 计数 + 头底 stone-300 线）、行、末行「+ 新建」add 按钮——不要把「新建」做成顶部填色按钮。库级动作（导入 / 预览 / 导出）放头部右侧作次级 ghost 按钮（stone-600、hover stone-100），与计数并排。
多字段项整块 hover含多字段的复合项（如「产出 = 路径+模板+必选」）与可展开行（展开后＝摘要+详情）都整块给 hover 底色（stone-100/45，同单行），而非只高亮其中某一行——视觉上是「一项」。可展开行的底线放在外层包裹上，展开时摘要与详情连成一体。展开详情内字段间距 16px（label+控件为一组），不用 24px。

13 — DESIGN PHILOSOPHY

Why it works

VISUAL SIGNATURE

钴蓝是品牌锚点，不是装饰。出现位置：logo、主 CTA、focused 卡片边框、active nav、用户头像。每一处都承担功能。

信号橙是 focus indicator。只用于：logo 中间那条横线、当前正在工作的需求标记、generate spec 按钮、focused 卡片左侧 3px 标记条。它是产品的"光标"——告诉用户"现在看这里"。

米底（paper #f5f1e8）做背景而不是冷白。长时间使用更舒服，差异化也强——大部分 SaaS 用 #fff 或 #f9fafb。

没有任何 drop-shadow。层级靠 border + 背景对比。这是 Klarit 区别于 Notion/Linear 的视觉签名——更"印刷品"，更不"软件"。

Mono 字体专门留给"产品的语言"——需求 ID、git refs、API endpoint。这强化了核心叙事：requirements 是和 code 同等重要的工程产物，配得上同样的字体仪式感。
